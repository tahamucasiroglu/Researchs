§ 1Tipler ve bellek

Derin sayfa: C# / .NET · 01 · Temel tipler, Bellek ve performans.

SoruKısa cevap
Değer tipi ile referans tipi farkı? MÜLAKATTA SIKDeğer tipi (int, struct, enum) atamada kopyalanır; referans tipi (class, string, dizi, delegate) atamada referans kopyalanır, iki değişken aynı nesneyi gösterir. Yer: değer tipi yerel değişkense genelde stack'te, bir sınıfın alanıysa o nesnenin içinde heap'te.
"Değer tipleri stack'te durur" doğru mu? TUZAKTam değil. Nerede durduğu değişkenin nerede tanımlandığına bağlı; sınıf alanı olan int heap'tedir, yakalanan (closure) yerel değişken de heap'e taşınır. Doğru cevap: "kopyalama semantiği" farkı.
struct mı class mı? MÜLAKATTA SIKstruct: küçük (≈16 bayt altı önerilir), değişmez, kimliği olmayan değer (koordinat, para). class: kimliği olan, büyük, kalıtım gereken, paylaşılan nesne. Büyük struct her geçişte kopyalanır → yavaş.
record nedir, class'tan farkı? MÜLAKATTA SIKrecord (varsayılan record class) değer eşitliği (Equals/== alanlara göre), ToString, with ifadesi ve kısa (positional) söz dizimi üretir. record struct (C# 10) değer tipli sürümü. DTO, olay (event), değişmez model için.
Boxing / unboxing? MÜLAKATTA SIKDeğer tipinin object veya arayüze çevrilmesi = boxing (heap'te kutu, bellek ayırma); geri çevirme = unboxing (tip kontrolü + kopya). Önlem: generics (List<int>, ArrayList değil), ToString() yerine generic API'ler.
string neden immutable? MÜLAKATTA SIKHer değişiklik yeni string üretir; güvenli paylaşım, thread-safe, hash sabit, interning mümkün. Döngüde += → O(n²) bellek; çözüm StringBuilder (ya da string.Join, string.Create).
StringBuilder ne zaman?Döngüde çok sayıda birleştirme. 2–3 parçalık birleştirmede + veya $"..." yeterli (derleyici optimize eder).
ref, out, in farkı? MÜLAKATTA SIKref: çağırmadan önce atanmış olmalı, metot okuyup değiştirebilir. out: metot atamak zorunda (TryParse deseni). in: salt okunur referans (büyük struct'ı kopyalamadan geçirmek). C# 12 ref readonly parametre de ekledi.
Nullable value type ve nullable reference type farkı?int? = Nullable<int>, gerçek bir tip (HasValue, Value). string? (C# 8, NRT) yalnız derleme zamanı uyarısı; çalışma zamanında tip aynı. Yeni şablonlarda <Nullable>enable</Nullable> açık.
?., ??, ??=, ! ??. null ise kısa devre; ?? null ise sağdaki; ??= null ise ata; ! (null-forgiving) derleyiciye "null değil" der, kontrol yapmaz. C# 14 YENİ: customer?.Order = x; sol tarafta da çalışır (null-conditional assignment).
const ve readonly farkı? MÜLAKATTA SIKconst: derleme zamanı sabiti, yalnız ilkel/string, çağıran derlemeye gömülür (kütüphanede değişirse çağıran yeniden derlenmeli). readonly: çalışma zamanında, kurucuda atanır, her tip olabilir. Paylaşılan sabit nesne → static readonly.
static sınıf / üye?static class örneklenemez, yalnız static üye (yardımcı metotlar, extension). Static alan tüm uygulamada tek kopya → thread güvenliğine dikkat. Static constructor tip ilk kullanıldığında bir kez çalışır.
var tip güvenli mi?Evet; tip derleme zamanında çıkarılır, dynamic değildir.

§ 2OOP anahtar kelimeleri

Derin sayfa: 01 · Nesne yönelimli. SOLID ve tasarım: 02.

SoruKısa cevap
abstract class ile interface farkı? MÜLAKATTA SIKAbstract class: durum (alan) ve kurucu tutar, tek kalıtım, "is-a". Interface: sözleşme, çoklu uygulanır, "can-do". C# 8'den beri interface'te default method, C# 11'den beri static abstract üye olabilir — fark artık esas olarak durum ve tekli kalıtım.
Interface default method ne işe yarar?Var olan arayüze, uygulayıcıları kırmadan yeni metot eklemek (API evrimi). Yalnız arayüz tipi üzerinden çağrılır.
virtual, override, new farkı? TUZAKvirtual + override = çok biçimlilik (çalışma zamanı tipine göre çağrı). new = gizleme; değişkenin derleme zamanı tipine göre çağrılır → sürpriz davranış.
sealed ne zaman?Kalıtılmasını istemediğin sınıf (tasarım niyeti + JIT devirtualization ile küçük performans kazancı). sealed override ile zinciri kesmek.
Erişim belirleyicileri?public, private (varsayılan üye), protected, internal (varsayılan tip; aynı assembly), protected internal, private protected, file (C# 11, aynı dosya).
Property ile field farkı?Field veri; property get/set metotları (kapsülleme, doğrulama, arayüzde tanımlanabilir). init (C# 9) yalnız nesne oluşturulurken atanır; required (C# 11) zorunlu atama. C# 14 YENİ: field anahtar kelimesi ile ayrı backing field yazmadan accessor gövdesi.
Primary constructor?C# 12'den beri sınıf ve struct'ta: class Servis(ILogger log). Parametre tüm gövdede kullanılır; DI ile sık. Parametre alan değildir, readonly değildir.
Extension method? MÜLAKATTA SIKstatic sınıfta, ilk parametresi this T olan static metot; tipi değiştirmeden ona metot ekliyormuş gibi çağrılır (LINQ böyle). C# 14 YENİ: extension(...) bloklarıyla extension property ve static extension üyeler.
Kapsülleme, kalıtım, çok biçimlilik, soyutlama?02 · OOP sayfasında tek satırlık tanımlar.

§ 3Generics, delegate, lambda

Derin sayfa: 01 · Generics, Delegate ve event.

SoruKısa cevap
Generics neden var?Tip güvenliği + yeniden kullanım + boxing yok. List<T> derleme zamanında tip kontrolü yapar.
Generic constraint'ler? MÜLAKATTA SIKwhere T : class / struct / new() / notnull / unmanaged / BaseSinif / IArayuz / T : U. C# 13: allows ref struct. Kısıt, T üzerinde hangi üyeleri çağırabileceğini belirler.
Kovaryans / kontravaryans? İLERİout T (kovaryans): IEnumerable<string> → IEnumerable<object>. in T (kontravaryans): Action<object> → Action<string>. Yalnız arayüz ve delegate'lerde, yalnız referans tiplerinde.
delegate nedir?Tip güvenli metot referansı. Func<T, TResult> değer döndürür, Action<T> döndürmez, Predicate<T> bool döndürür. Kendi delegate tipini yazmak artık nadir.
event ile delegate farkı? MÜLAKATTA SIKevent, delegate alanını kapsüller: dışarıdan yalnız += / -=; çağırma ve atama yalnız sahibi sınıfta. Abonelikten çıkılmazsa bellek sızıntısı (yayıncı aboneyi canlı tutar).
Lambda ve closure? MÜLAKATTA SIKLambda = isimsiz fonksiyon. Dış değişkeni kullanırsa closure oluşur: değişkenin kendisini yakalar (değerini değil), derleyici onu heap'teki bir sınıfa taşır.
Döngüde closure tuzağı? TUZAKfor (int i...) içinde () => i hepsi son değeri görür (tek değişken). foreach değişkeni C# 5'ten beri her turda yenidir. Çözüm: döngü içinde yerel kopya.
static lambda?static x => x * 2 dış değişken yakalamayı derleme hatasına çevirir; istemeden bellek ayırmayı önler.
csharp
var islemler = new List<Action>();
for (int i = 0; i < 3; i++) islemler.Add(() => Console.Write(i)); // 333
for (int i = 0; i < 3; i++) { int k = i; islemler.Add(() => Console.Write(k)); } // 012

§ 4LINQ ve iterator

Derin sayfa: 01 · LINQ, Diğer: iterator.

SoruKısa cevap
Deferred execution nedir? MÜLAKATTA SIKWhere, Select, OrderBy sorguyu tanımlar, çalıştırmaz; sonuç enumerate edilince (foreach, ToList, Count, First, Sum) çalışır. Her enumerate'te yeniden çalışır → çoklu sayım (multiple enumeration) uyarısı.
Hangi metotlar hemen çalışır?ToList, ToArray, ToDictionary, Count, Any, First/Single/Last, Sum/Min/Max/Average, Aggregate.
IEnumerable ile IQueryable farkı? MÜLAKATTA SIKIEnumerable<T>: bellekte, Func ile filtreler (LINQ to Objects). IQueryable<T>: expression tree tutar, sağlayıcı (EF Core) onu SQL'e çevirir. EF'de erken AsEnumerable()/ToList() → tüm tablo belleğe çekilir, filtre C#'ta çalışır.
IEnumerable, ICollection, IList, List farkı?IEnumerable: yalnız gezinme. ICollection: + Count, Add, Remove. IList: + indeks. List<T>: somut sınıf. Parametrede en dar arayüz, dönüşte ihtiyaç kadar somut. IReadOnlyList<T> salt okunur dönüş için iyi.
First, FirstOrDefault, Single, SingleOrDefault? MÜLAKATTA SIKFirst: ilk eleman, yoksa istisna. FirstOrDefault: yoksa default. Single: tam bir eleman olmalı; 0 veya >1 ise istisna. SingleOrDefault: 0 → default, >1 → istisna. Single tüm diziyi kontrol eder (SQL'de TOP 2).
Any() mi Count() > 0 mı?Any(): ilk elemanı bulunca durur. Count() hepsini sayabilir (koleksiyonda Count özelliği varsa hızlı). EF'de Any → EXISTS.
Select ile SelectMany?Select 1→1 dönüşüm; SelectMany 1→çok, iç içe listeleri düzleştirir.
GroupBy ile ToLookup?GroupBy deferred; ToLookup hemen çalışır, indekslenebilir sözlük gibi.
.NET 10'da yeni LINQ? YENİLeftJoin ve RightJoin operatörleri; EF Core 10 bunları LEFT/RIGHT JOIN'e çevirir (eskiden GroupJoin + SelectMany + DefaultIfEmpty).
yield return nedir? MÜLAKATTA SIKDerleyici bir durum makinesi (iterator) üretir; elemanlar istendikçe tek tek üretilir (tembel). Büyük/sonsuz diziler, akış işleme. yield break bitirir. Metottaki doğrulama da ilk MoveNext'e kadar çalışmaz.
IAsyncEnumerable<T>?async + yield return ile asenkron akış; await foreach ile tüketilir. EF Core AsAsyncEnumerable, ASP.NET Core akış cevapları.

§ 5IDisposable, GC, exception

Derin sayfa: 01 · Bellek, Exception.

SoruKısa cevap
IDisposable ve using neden? MÜLAKATTA SIKGC yalnız yönetilen belleği toplar; dosya, soket, DB bağlantısı gibi yönetilmeyen kaynaklar Dispose() ile hemen bırakılır. using bloğu/bildirimi, istisna olsa bile Dispose çağırır (try/finally). Async kaynak: IAsyncDisposable + await using.
Finalizer (~Sinif) ile Dispose farkı?Finalizer GC'nin belirsiz zamanında çalışır, nesneyi bir nesil daha yaşatır, pahalıdır. Dispose deterministik. Dispose pattern: Dispose(bool) + GC.SuppressFinalize(this). Çoğu sınıfa finalizer gerekmez (SafeHandle kullan).
GC nasıl çalışır? MÜLAKATTA SIKNesilli (generational): Gen 0 (yeni, sık toplanır) → Gen 1 (tampon) → Gen 2 (uzun ömürlü, nadir, pahalı). Kökten (stack, static, GC handle) ulaşılamayan nesneler toplanır; mark → sweep → compact.
LOH nedir?Large Object Heap: 85.000 bayt ve üstü nesneler; Gen 2 ile toplanır, varsayılan olarak sıkıştırılmaz (parçalanma). Büyük tamponlarda ArrayPool<T> kullan.
Workstation ve Server GC?Workstation: masaüstü, düşük gecikme. Server: çekirdek başına heap, yüksek throughput; ASP.NET Core varsayılanı Server GC.
GC.Collect() çağırmalı mıyım?Hayır (ölçüm/teşhis dışında). GC kendi sezgisini bozar.
Bellek sızıntısı .NET'te olur mu?Evet: abonelikten çıkılmamış event, static koleksiyonda biriken nesne, Dispose edilmemiş kaynak, sonsuz cache, yanlış ömürlü singleton.
throw ile throw ex farkı? MÜLAKATTA SIKthrow; orijinal stack trace'i korur. throw ex; stack trace'i o satıra sıfırlar → hatanın kaynağı kaybolur. Sarmalamak gerekirse throw new XException("…", ex) (InnerException).
finally ne zaman çalışır?try'dan normal çıkışta, istisnada, return'de. Çalışmayan durum: süreç çökmesi, Environment.FailFast, StackOverflow.
Exception filter?catch (HttpRequestException ex) when (ex.StatusCode == 404) — stack açılmadan koşul değerlendirilir.
İstisnayı akış kontrolü için kullanmak?Kötü: pahalı ve okunaksız. Beklenen durumlar için TryParse deseni, Result tipi veya bool dönüş.
Global hata yönetimi (ASP.NET Core)?UseExceptionHandler + IExceptionHandler (.NET 8+) + AddProblemDetails → RFC 9457 biçiminde hata cevabı.

§ 6async / await

Derin sayfa: 01 · Async. En yüksek getirili üç konudan biri (İş arama § 6.1).

SoruKısa cevap
async/await ne yapar? MÜLAKATTA SIKDerleyici metodu bir durum makinesine çevirir; await tamamlanmamış bir işte thread'i bırakır, iş bitince devam eder. Amaç I/O beklerken thread bloklamamak (ölçeklenebilirlik), daha hızlı CPU işi değil.
async yeni thread açar mı? TUZAKHayır. I/O işlerinde beklenirken hiçbir thread meşgul değildir. CPU işini başka thread'e atmak için Task.Run gerekir (ASP.NET Core'da gereksiz; zaten thread pool'dasın).
Task ile Thread farkı?Thread: işletim sistemi iş parçacığı, pahalı. Task: tamamlanacak bir işin temsili (promise); çoğu zaman thread pool'da veya hiç thread kullanmadan (I/O) çalışır.
Task ile ValueTask farkı? MÜLAKATTA SIKValueTask<T> struct'tır; sonuç çoğu zaman senkron hazırsa (cache) bellek ayırmayı önler. Kurallar: yalnız bir kez await et, aynı anda iki kez await etme, tamamlanmadan .Result alma. Şüphedeysen Task.
async void neden kötü? MÜLAKATTA SIKÇağıran bekleyemez, istisnayı yakalayamaz (süreç çökebilir), test edilemez. Yalnız olay işleyicilerinde (event handler). Diğer her yerde async Task.
Deadlock nasıl oluşur? MÜLAKATTA SIKSynchronizationContext olan ortamda (WinForms/WPF UI, klasik ASP.NET) .Result / .Wait() ile bloklamak: devam (continuation) aynı thread'e dönmek ister, thread ise beklemede. Çözüm: baştan sona async ("async all the way"), bloklama yok.
ASP.NET Core'da bu deadlock olur mu?ASP.NET Core'da SynchronizationContext yok, klasik deadlock olmaz; ama .Result yine de thread pool'u tüketir (thread pool starvation). Kullanma.
ConfigureAwait(false) ne zaman? MÜLAKATTA SIKDevamın orijinal bağlama dönmesine gerek olmayan kütüphane kodunda. UI kodunda kullanma (UI thread'ine dönmek gerekir). ASP.NET Core uygulama kodunda etkisi yok denecek kadar az.
Task.WhenAll ile sırayla await farkı?Bağımsız işler WhenAll ile paralel beklenir → toplam süre en uzun iş kadar. Sırayla await → süreler toplanır. İstisnalar: await WhenAll ilkini fırlatır, hepsi task.Exception'da.
CancellationToken neden?Uzun işi iptal etmek; ASP.NET Core'da HttpContext.RequestAborted istemci ayrılınca iptal eder. Zinciri sonuna kadar geçir.
lock içinde await?Derlenmez. Asenkron kilit için SemaphoreSlim.WaitAsync. .NET 9+ System.Threading.Lock tipi lock ile daha verimli çalışır.
Thread güvenli koleksiyon?ConcurrentDictionary, ConcurrentQueue, Channel<T> (üretici–tüketici), basit sayaç için Interlocked.Increment.
csharp
// Kötü: UI veya eski ASP.NET'te deadlock, ASP.NET Core'da thread pool israfı
var veri = servis.GetirAsync().Result;
// İyi
var veri = await servis.GetirAsync(cancellationToken);

§ 7Span, pattern matching, eşitlik

SoruKısa cevap
Span<T> nedir? ORTADizi, stack belleği (stackalloc) veya yönetilmeyen bellek üzerinde kopyasız dilim (slice). ref struct'tır: yalnız stack'te yaşar, sınıf alanı olamaz, await boyunca tutulamaz. Heap'e/async'e taşımak için Memory<T>.
Span ne kazandırır?Alt string/dizi için yeni bellek ayırmadan parse (ReadOnlySpan<char>); daha az GC. C# 14 YENİ: T[], Span<T>, ReadOnlySpan<T> arasında örtük dönüşümler (first-class span).
Pattern matching örnekleri?is int n, is null / is not null, switch expression (x switch { > 0 => "pozitif", _ => "diğer" }), property pattern ({ Durum: "Aktif" }), relational/logical (C# 9: >, and, or, not), list pattern (C# 11: [1, .., var son]).
is null mı == null mı?is null operatör aşırı yüklemesinden etkilenmez, her zaman gerçek null kontrolü.
== ile Equals farkı? MÜLAKATTA SIKReferans tiplerinde == varsayılan olarak referans eşitliği, Equals sanal ve ezilebilir. string, =='yi değer karşılaştırmasına aşırı yükler. record ikisini de değer eşitliği yapar. Kesin referans kontrolü: ReferenceEquals.
GetHashCode sözleşmesi? MÜLAKATTA SIKEquals true olan iki nesnenin hash'i eşit olmalı (tersi gerekmez). Equals'ı ezen GetHashCode'u da ezer (HashCode.Combine). Sözlük anahtarının hash'e giren alanı değişmemeli, yoksa nesne sözlükte "kaybolur".
Reflection ne zaman?Çalışma zamanında tip/üye inceleme (serileştirme, DI, eklenti). Yavaş ve Native AOT/trimming ile sorunlu; mümkünse source generator.
