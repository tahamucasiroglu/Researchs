§ 1Pipeline, DI ve yapılandırma

Derin sayfa: C# / .NET · 02 · DI, Middleware, Configuration.

SoruKısa cevap
Middleware nedir? MÜLAKATTA SIKİstek ve cevabın geçtiği zincir halkası; her halka işini yapıp next() ile sonrakine verir veya kısa devre yapar (cevabı kendi döner). Cevap zinciri ters sırayla geri döner.
Use, Run, Map farkı?Use: sonrakine devredebilen middleware. Run: terminal, zinciri bitirir. Map/MapWhen: yola/koşula göre dal açar.
Middleware sırası neden önemli? MÜLAKATTA SIKKayıt sırası = çalışma sırası. Tipik: ExceptionHandler → HSTS → HttpsRedirection → Static files → Routing → CORS → Authentication → Authorization → özel middleware → endpoint'ler. UseAuthorization, UseAuthentication'dan önce olursa kullanıcı tanınmaz.
Kendi middleware'imi nasıl yazarım?InvokeAsync(HttpContext ctx, RequestDelegate next) olan sınıf + app.UseMiddleware<T>(), ya da satır içi app.Use(async (ctx, next) => { ...; await next(ctx); }). Örnek: korelasyon kimliği, istek süresi loglama.
DI yaşam süreleri? MÜLAKATTA SIKTransient: her istendiğinde yeni örnek. Scoped: HTTP isteği başına bir örnek (DbContext varsayılanı). Singleton: uygulama boyunca tek örnek, thread-safe olmalı.
Captive dependency nedir? MÜLAKATTA SIKUzun ömürlü servisin kısa ömürlüyü yakalaması: singleton içine scoped enjekte edilirse scoped servis fiilen singleton olur (ör. tek DbContext tüm isteklerde → thread hatası, bayat veri). Development ortamında scope doğrulaması bunu başlangıçta istisnayla yakalar. Çözüm: singleton'da IServiceScopeFactory.CreateScope().
Transient'i singleton'a enjekte edersem?Transient de singleton kadar yaşar (yalnız bir kez oluşturulur); durumsuzsa sorun yok, durumluysa hata.
Keyed services?.NET 8+: aynı arayüzün birden çok uygulamasını anahtarla kaydet (AddKeyedSingleton<IOdeme, Kart>("kart")), [FromKeyedServices("kart")] ile al. Strategy deseni için.
Configuration kaynak sırası? MÜLAKATTA SIKVarsayılan: appsettings.json → appsettings.{Environment}.json → User Secrets (yalnız Development) → ortam değişkenleri → komut satırı. Sonraki öncekini ezer. Sır asla appsettings.json'a/depoya yazılmaz.
Options pattern? MÜLAKATTA SIKAyar bölümünü tipli sınıfa bağla: services.Configure<SmtpAyar>(config.GetSection("Smtp")). IOptions<T>: singleton, değişikliği görmez. IOptionsSnapshot<T>: scoped, istek başına yeniden okur. IOptionsMonitor<T>: singleton, değişiklik bildirimi. ValidateDataAnnotations().ValidateOnStart() ile açılışta doğrula.
Ortamlar (Environment)?ASPNETCORE_ENVIRONMENT = Development / Staging / Production; app.Environment.IsDevelopment().
Kestrel nedir?ASP.NET Core'un yerleşik, platformlar arası web sunucusu. Önünde IIS, Nginx, YARP gibi reverse proxy olabilir (TLS, yük dengeleme).
new HttpClient() neden yapılmaz? MÜLAKATTA SIKHer seferinde yeni nesne → socket tükenmesi (TIME_WAIT); tek static örnek → DNS değişikliğini görmez. Çözüm: IHttpClientFactory (named/typed client), dayanıklılık için AddStandardResilienceHandler (retry, timeout, circuit breaker).

§ 2Endpoint'ler: controller, minimal API, filtre, doğrulama

Derin sayfa: 02 · Web API, Filters, Routing.

SoruKısa cevap
Minimal API mi controller mı? MÜLAKATTA SIKMinimal API: az tören, hızlı, küçük servis/mikroservis; MapGet, MapGroup, TypedResults. Controller: büyük API'de düzen, filtre ve konvansiyon zenginliği. İkisi aynı uygulamada birlikte olabilir; Microsoft yeni projelerde minimal API'yi öneriyor.
Routing türleri?Attribute routing ([Route("api/siparisler")], [HttpGet("{id:int}")]) API'lerde standart; conventional ({controller}/{action}/{id?}) MVC'de. {id:int} gibi route constraint.
Model binding kaynakları?[FromRoute], [FromQuery], [FromBody] (tek bir parametre), [FromHeader], [FromForm], [FromServices]. [ApiController] karmaşık tipi varsayılan olarak body'den alır.
Doğrulama nasıl? MÜLAKATTA SIKDataAnnotations ([Required], [Range]) veya FluentValidation. [ApiController] geçersiz modelde otomatik 400 + ValidationProblemDetails döner. .NET 10 YENİ: minimal API'de builder.Services.AddValidation() ile yerleşik doğrulama; uç bazında .DisableValidation().
Filtre türleri ve sırası? MÜLAKATTA SIKMVC: Authorization → Resource → (model binding) → Action → (action) → Exception → Result. Kesişen işler (loglama, doğrulama, önbellek) için. Minimal API'de IEndpointFilter / AddEndpointFilter.
Filtre ile middleware farkı?Middleware her isteği görür, MVC'den habersiz. Filtre MVC/endpoint bağlamında: hangi action, model, argümanlar.
Hata cevabı standardı?ProblemDetails (RFC 9457): type, title, status, detail, instance. AddProblemDetails() + UseExceptionHandler(). Hata ayrıntısı (stack trace) üretimde dönülmez.
OpenAPI / Swagger? YENİ.NET 9'dan beri şablonda Swashbuckle yok; yerleşik Microsoft.AspNetCore.OpenApi (AddOpenApi, MapOpenApi). .NET 10'da varsayılan OpenAPI 3.1. Arayüz için Swagger UI veya Scalar ayrıca eklenir.

§ 3Güvenlik: kimlik, yetki, JWT, CORS

Derin sayfa: 02 · Kimlik doğrulama ve yetkilendirme.

SoruKısa cevap
Authentication ile authorization farkı? MÜLAKATTA SIKAuthentication (kimlik doğrulama): kimsin? Authorization (yetkilendirme): bunu yapmaya iznin var mı? Önce kimlik, sonra yetki.
401 ile 403 farkı? MÜLAKATTA SIK401 Unauthorized: kimlik yok/geçersiz (adı yanıltıcı, aslında "unauthenticated"). 403 Forbidden: kimlik belli ama yetki yok.
Role-based ve policy-based farkı?Rol: [Authorize(Roles = "Admin")]. Policy: kural (requirement + handler), ör. "18 yaş üstü", "kaynağın sahibi". Karmaşık yetki için policy.
JWT yapısı? MÜLAKATTA SIKheader.payload.signature, Base64Url kodlu. Payload'da claim'ler: sub, exp, iss, aud, roller. İmzalı, şifreli değil: herkes okuyabilir, içine sır konmaz. Sunucu imzayı (HS256 paylaşılan anahtar / RS256 açık-özel anahtar), exp, iss, aud'u doğrular.
JWT nasıl iptal edilir?Kendiliğinden edilemez (durumsuz). Çözüm: kısa ömürlü access token (5–15 dk) + refresh token (sunucuda saklanır, iptal edilebilir, döndürülür/rotation); gerekirse kara liste.
Token nerede saklanır? ÇELİŞKİLİTarayıcıda localStorage XSS'e açık; HttpOnly + Secure + SameSite cookie XSS'e dayanıklı ama CSRF önlemi ister. SPA'lar için güncel öneri BFF (Backend for Frontend) deseni. Tek doğru cevap yok, artı/eksi sayılır.
Cookie ile JWT farkı?Cookie: sunucu oturumu veya şifreli bilet, tarayıcı otomatik gönderir. JWT: istemci Authorization: Bearer başlığıyla gönderir; mobil ve servisler arası için uygun. .NET 10: API uçlarında cookie auth giriş sayfasına yönlendirmek yerine 401/403 döner YENİ.
OAuth 2.0 ile OpenID Connect farkı?OAuth 2.0 yetki devri (access token), OIDC onun üstüne kimlik katmanı (ID token, kullanıcı bilgisi). "Google ile giriş" = OIDC.
CORS nedir? MÜLAKATTA SIKTarayıcının farklı origin'e (şema + alan + port) JavaScript isteğini engellemesi; sunucu Access-Control-Allow-Origin ile izin verir. Basit olmayan isteklerde önce OPTIONS preflight. CORS bir sunucu güvenliği değildir: Postman/curl'ü engellemez. AllowAnyOrigin + AllowCredentials birlikte kullanılamaz.
Parola nasıl saklanır?Düz SHA-256 değil: yavaş, tuzlu (salt) algoritma — PBKDF2 (ASP.NET Core Identity PasswordHasher), bcrypt, Argon2.
OWASP'tan ne sorulur?SQL injection (parametreli sorgu), XSS (çıktı kodlama), CSRF (antiforgery token, SameSite), kırık erişim kontrolü (IDOR: başkasının id'sini denemek), hassas veri ifşası, güvenlik yanlış yapılandırması.

§ 4HTTP ve REST

SoruKısa cevap
REST ilkeleri? MÜLAKATTA SIKİstemci–sunucu, stateless (her istek kendi bilgisini taşır), önbelleklenebilir, tek tip arayüz (kaynak + URI + HTTP fiili + temsil), katmanlı sistem; isteğe bağlı code-on-demand. Kaynak isim, çoğul: GET /siparisler/42, fiil URL'de değil HTTP metodunda.
HTTP fiilleri? MÜLAKATTA SIKGET oku · POST oluştur / işlem · PUT tamamen değiştir (yoksa oluşturabilir) · PATCH kısmen değiştir · DELETE sil · HEAD yalnız başlık · OPTIONS izinler (CORS preflight).
Safe ve idempotent nedir? MÜLAKATTA SIKSafe: sunucu durumunu değiştirmez (GET, HEAD, OPTIONS). Idempotent: aynı istek N kez = 1 kez etkisi (GET, PUT, DELETE, HEAD, OPTIONS). POST idempotent değil, PATCH garanti değil.
POST'u idempotent yapmak? MÜLAKATTA SIKİstemci Idempotency-Key başlığı gönderir; sunucu anahtar + sonucu saklar, tekrar gelirse aynı cevabı döner, işlemi tekrarlamaz. Ödeme, sipariş, ağ zaman aşımında tekrar deneme için şart.
Durum kodları? MÜLAKATTA SIK200 OK · 201 Created (+ Location) · 204 No Content · 301/302 yönlendirme · 304 Not Modified · 400 Bad Request · 401 · 403 · 404 · 409 Conflict (eşzamanlılık, tekrar kayıt) · 422 Unprocessable (anlam hatası) · 429 Too Many Requests · 500 · 502 Bad Gateway · 503 Service Unavailable · 504 Gateway Timeout.
PUT ile PATCH farkı?PUT kaynağın tam temsilini gönderir (eksik alan = boşalır); PATCH yalnız değişeni (JSON Patch veya JSON Merge Patch).
Sayfalama??page=2&pageSize=20 (offset, basit ama derin sayfada yavaş) veya cursor/keyset (?after=123, büyük veride hızlı ve tutarlı).
API versioning?URL (/api/v1/..., en yaygın), query (?api-version=1.0), başlık, media type. ASP.NET Core'da yerleşik değil, Asp.Versioning paketleri. Kırıcı değişiklikte yeni sürüm, eskiyi bir süre Deprecated işaretle.
Rate limiting? ORTA.NET 7'den beri yerleşik: AddRateLimiter + UseRateLimiter; algoritmalar fixed window, sliding window, token bucket, concurrency; reddedilene 429 (+ Retry-After). Çok sunuculu yapıda dağıtık sınır için Redis veya API gateway.
Önbellek seçenekleri?Response caching (HTTP başlıkları), output caching (.NET 7, sunucuda), IMemoryCache, IDistributedCache (Redis), HybridCache (.NET 9: bellek + dağıtık, cache stampede koruması).

§ 5Loglama, sağlık, arka plan işleri

SoruKısa cevap
Yapılandırılmış loglama? MÜLAKATTA SIKlogger.LogInformation("Sipariş {SiparisId} oluşturuldu", id) — mesaj şablonu, string interpolation değil; alanlar ayrı aranabilir. Seviyeler: Trace, Debug, Information, Warning, Error, Critical. Serilog / OpenTelemetry ile merkezi toplama. Kişisel veri ve sır loglanmaz.
Neden $"..." ile loglanmaz?Şablon kaybolur (aranamaz), log seviyesi kapalı olsa bile string oluşturulur. Yüksek performans için [LoggerMessage] source generator.
Health check?AddHealthChecks().AddNpgSql(...) + MapHealthChecks("/health"). Liveness (süreç ayakta mı) ve readiness (bağımlılıklar hazır mı, trafik alabilir mi) ayrı uçlar; Kubernetes ve yük dengeleyici kullanır.
Arka plan işi? MÜLAKATTA SIKBackgroundService (IHostedService) → ExecuteAsync içinde stoppingToken ile döngü. Singleton olduğu için scoped servis (DbContext) için scope aç. Kalıcılık, tekrar deneme ve zamanlama gerekiyorsa Hangfire / Quartz.NET; kuyruk tüketimi için mesajlaşma.
Gözlemlenebilirliğin üç ayağı?Log, metric, trace (dağıtık izleme, korelasyon kimliği). .NET'te OpenTelemetry standardı. Derin: 07 · Gözlemlenebilirlik.

§ 6EF Core

Derin sayfa: 03 · EF Core çekirdek, Sorgulama ve performans, Migration, Dapper.

SoruKısa cevap
DbContext ömrü? MÜLAKATTA SIKScoped (istek başına), thread-safe değil: aynı context'te paralel sorgu yok. Arka plan işi/Blazor için IDbContextFactory; yüksek yükte AddDbContextPool.
Change tracking nedir?DbContext yüklediği varlıkların ilk hâlini tutar; SaveChanges farkları bulup INSERT/UPDATE/DELETE üretir. Durumlar: Added, Modified, Deleted, Unchanged, Detached.
Tracking ile AsNoTracking? MÜLAKATTA SIKYalnız okuma (liste, rapor) için AsNoTracking(): daha az bellek ve CPU. Güncelleyeceksen tracking. Aynı satır birden çok kez dönüyorsa AsNoTrackingWithIdentityResolution.
N+1 problemi nedir? MÜLAKATTA SIK1 sorgu ile ana liste (N sipariş), sonra her biri için ilişkili veriye ayrı sorgu → N+1 sorgu. Genelde lazy loading + döngüde navigation erişimi. Çözüm: Include/ThenInclude (eager), projeksiyon (Select ile yalnız gereken alanlar — çoğu zaman en iyisi), gerekirse AsSplitQuery(). Teşhis: SQL loglarını aç.
Eager, lazy, explicit loading? MÜLAKATTA SIKEager: Include ile aynı sorguda. Lazy: navigation'a ilk erişimde otomatik sorgu (Microsoft.EntityFrameworkCore.Proxies, virtual navigation) — N+1 riski. Explicit: context.Entry(x).Collection(c => c.Kalemler).LoadAsync() ile elle.
Cartesian explosion / split query?Birden çok koleksiyonu Include etmek JOIN satırlarını çarpar. AsSplitQuery() her koleksiyonu ayrı sorguda çeker (tutarlılık riski var; EF 10 sıralamayı düzeltti).
Migration akışı? MÜLAKATTA SIKdotnet ef migrations add Ad → kodla şema farkı; dotnet ef database update uygular. Üretimde öneri: dotnet ef migrations script --idempotent ile SQL betiği veya migration bundle; çok örnekli uygulamada açılışta Migrate() çağırmak yarış durumu yaratabilir. Geri alma: önceki migration'a update.
Transaction? MÜLAKATTA SIKTek SaveChanges zaten tek transaction. Birden çok SaveChanges veya ham SQL için await using var tx = await db.Database.BeginTransactionAsync(); ... await tx.CommitAsync();. Tekrar deneme stratejisi (execution strategy) varsa transaction onun içinde çalıştırılır.
Concurrency token? MÜLAKATTA SIKOptimistic concurrency: [Timestamp] (SQL Server rowversion) veya [ConcurrencyCheck]; UPDATE ... WHERE Id=@id AND Version=@v, etkilenen satır 0 ise DbUpdateConcurrencyException → kullanıcıya 409 veya yeniden dene. Pessimistic: satırı kilitlemek (SELECT ... FOR UPDATE / UPDLOCK), nadir.
Raw SQL güvenli mi? MÜLAKATTA SIKFromSql($"... WHERE Id = {id}") (FormattableString) ve SqlQuery<T> parametreleştirir, güvenli. FromSqlRaw + string birleştirme SQL injection'a açık; EF 10 bunun için analizör uyarısı verir YENİ.
Toplu güncelle/sil?ExecuteUpdateAsync / ExecuteDeleteAsync (EF 7+): varlık yüklemeden tek SQL. Change tracker'ı güncellemez. EF 10'da ExecuteUpdateAsync normal lambda alır.
Global query filter?HasQueryFilter(x => !x.Silindi) — soft delete, çok kiracılık. EF 10 YENİ: adlandırılmış filtreler, IgnoreQueryFilters(["SoftDelete"]) ile yalnız birini kapatma.
EF Core mu Dapper mı? MÜLAKATTA SIKEF Core: LINQ, change tracking, migration, ilişkiler; verimlilik. Dapper: elle SQL, ince eşleme, en yüksek kontrol ve hız; tracking ve migration yok. Sık cevap: yazma ve iş kuralı EF Core, ağır rapor/okuma sorguları Dapper veya ham SQL.
EF Core sorgu yavaşsa?SQL'i logla, execution plan'e bak, indeks ekle, projeksiyon ve AsNoTracking, sayfalama, N+1 kontrolü, compiled query, gerekirse ham SQL.
EF Core 10 hakkında? YENİKasım 2025, LTS, 10 Kasım 2028'e kadar destek; .NET 10 gerektirir. LeftJoin/RightJoin, complex type'ların JSON'a eşlenmesi, adlandırılmış query filter, SQL Server 2025 vector ve json tipleri.

§ 7SQL özeti

Ayrıntılı soru–cevaplar ayrı rehberde: SQL mülakat rehberi. Buradakiler yalnız en sık 6 soru.

SoruKısa cevap
JOIN türleri? MÜLAKATTA SIKINNER (iki tarafta eşleşen), LEFT (soldaki hepsi + eşleşen, yoksa NULL), RIGHT, FULL OUTER, CROSS (kartezyen), self join.
WHERE ile HAVING farkı? MÜLAKATTA SIKWHERE gruplamadan önce satırları süzer; HAVING GROUP BY'dan sonra grupları (toplama fonksiyonlarıyla) süzer.
Clustered ve non-clustered index? MÜLAKATTA SIKClustered: tablonun fiziksel sırası, tabloda bir tane (genelde PK). Non-clustered: ayrı yapı + satıra işaretçi, birden çok olabilir. İndeks okumayı hızlandırır, yazmayı yavaşlatır.
ACID ve isolation level? MÜLAKATTA SIKAtomicity, Consistency, Isolation, Durability. Seviyeler: Read Uncommitted (dirty read) → Read Committed (çoğu motorun varsayılanı) → Repeatable Read → Serializable; SQL Server'da ayrıca Snapshot.
Normalizasyon?Tekrarı ve güncelleme anomalisini azaltmak: 1NF (atomik değer), 2NF (kısmi bağımlılık yok), 3NF (geçişli bağımlılık yok). Rapor/okuma için bilinçli denormalizasyon olabilir.
SQL injection'dan korunma?Parametreli sorgu (EF, Dapper parametreleri, SqlParameter); string birleştirme yok; en az yetkili DB kullanıcısı.
