§ 1Sorgunun mantıksal çalışma sırası

Yazım sırası SELECT … FROM … WHERE … olsa da veritabanı sorguyu şu sırayla mantıksal olarak işler:

AdımCümleNe yapar

2WHERESatırları süzer (toplama fonksiyonu yok)

SELECT Maas * 2 AS m FROM Calisan WHERE m > 10000;   -- PostgreSQL / SQL Server / MySQL: hata
SELECT Maas * 2 AS m FROM Calisan WHERE Maas * 2 > 10000;   -- doğru: ifadeyi tekrar yaz

Alias 5. adımda doğar, WHERE 2. adımda çalışır; bu yüzden standart SQL'de WHERE alias'ı göremez. ORDER BY ise alias'ı görür; PostgreSQL ve SQL Server HAVING'de görmez. MySQL alias'ı WHERE'de reddeder, GROUP BY / HAVING / ORDER BY'da kabul eder Resmî. SQLite WHERE'de de kabul eder Ölçüldü — taşınabilir değil, mülakatta güvenme.

§ 2JOIN'ler ve "kaç satır gelir?" Mülakatta sık

Örnek veri

CREATE TABLE Ogrenci (Id INTEGER PRIMARY KEY, Ad TEXT);
INSERT INTO Ogrenci VALUES (1, 'Ali'), (2, 'Ayse');      -- Ali kurs almış, Ayse almamış

CREATE TABLE OgrenciKurs (OgrenciId INTEGER, Kurs TEXT);
INSERT INTO OgrenciKurs VALUES (1, 'C#'), (1, 'SQL');    -- yalnız Ali'nin 2 kursu

Ortak gövde: SELECT o.Ad, k.Kurs FROM Ogrenci o <JOIN> OgrenciKurs k ON k.OgrenciId = o.Id;

Sonuçlar Ölçüldü

JOINSonuç (Ad – Kurs)Satır
INNER JOIN = JOINAli–C#, Ali–SQL2
LEFT JOIN = LEFT OUTER JOINAli–C#, Ali–SQL, Ayse–NULL3
RIGHT JOIN = RIGHT OUTER JOINAli–C#, Ali–SQL (sağdaki her satırın eşi var)2
FULL OUTER JOINAli–C#, Ali–SQL, Ayse–NULL3
CROSS JOIN (ON yok)Ali–C#, Ali–SQL, Ayse–C#, Ayse–SQL4 = 2×2
  • INNER: yalnız iki tarafta da eşi olanlar.
  • LEFT: soldaki her satır en az bir kez gelir; eşi yoksa sağ kolonlar NULL.
  • RIGHT: LEFT'in aynası; A RIGHT JOIN B = B LEFT JOIN A (kolon sırası hariç).
  • FULL OUTER: LEFT ∪ RIGHT; iki taraftaki eşsizler de NULL'la gelir.
  • CROSS: Kartezyen çarpım, her satır × her satır.
  • SELF: tablo kendisiyle birleşir (aşağıda).

Anahtar cümleler

"LEFT JOIN ile LEFT OUTER JOIN aynıdır." · "JOIN tek başına INNER JOIN demektir." · "OUTER kelimesi isteğe bağlıdır." · "Eşleşmeyen tarafın kolonları NULL gelir."

Satır sayısı formülleri

Solda a, sağda b satır:

JOINEn azEn çok
INNER0a×b
LEFTaa×b
RIGHTba×b
FULLmax(a,b)a×b; hiç eşleşme yoksa a+b
CROSSa×ba×b
  • Çoklu eşleşme çoğaltır: soldaki bir satır sağda 3 satırla eşleşirse 3 satır olur. Sol tarafta iki tane 1, sağda üç tane 1 → INNER 6 satır Ölçüldü.
  • NULL anahtar eşleşmez: NULL = NULL doğru değildir; iki tarafta da NULL olsa INNER'da gelmez.
  • Anahtar bir tarafta benzersizse (PK–FK): LEFT'te "çok" taraf soldaysa sonuç tam olarak sol satır sayısıdır.

Anti-join: eşi olmayanlar

SELECT o.Ad
FROM Ogrenci o
LEFT JOIN OgrenciKurs k ON k.OgrenciId = o.Id
WHERE k.OgrenciId IS NULL;            -- Ayse (1 satır)

-- aynı iş:
SELECT o.Ad FROM Ogrenci o
WHERE NOT EXISTS (SELECT 1 FROM OgrenciKurs k WHERE k.OgrenciId = o.Id);

NULL kontrolünü sağ tablonun NULL olamayan bir kolonunda (join anahtarı ya da PK) yap; zaten NULL olabilen kolonda yanlış sonuç verir.

Klasik tuzak: koşul ON'da mı WHERE'de mi?

-- A) Koşul ON'da: sol taraf korunur → 2 satır (Ali–SQL, Ayse–NULL)
SELECT o.Ad, k.Kurs FROM Ogrenci o
LEFT JOIN OgrenciKurs k ON k.OgrenciId = o.Id AND k.Kurs = 'SQL';
-- B) Koşul WHERE'de: LEFT JOIN fiilen INNER'a döner → 1 satır (Ali–SQL)
SELECT o.Ad, k.Kurs FROM Ogrenci o
LEFT JOIN OgrenciKurs k ON k.OgrenciId = o.Id
WHERE k.Kurs = 'SQL';

Kural

Sağ tabloya ait süzgeç ON'a, sonucun tamamına ait süzgeç WHERE'e. Ayse'nin Kurs'u NULL'dır; NULL = 'SQL' doğru olmadığı için WHERE onu atar. INNER JOIN'de ikisi arasında fark yoktur.

SELF JOIN

SELECT c.Ad AS Calisan, y.Ad AS Yonetici
FROM Calisan c
LEFT JOIN Calisan y ON y.Id = c.YoneticiId;   -- iki farklı alias şart

5 çalışan, biri yöneticisiz: LEFT ile 5, INNER ile 4 satır (en üstteki yönetici düşer) Ölçüldü.

Üç tablo

Kurs = C#, SQL, Python (Python'u kimse almamış); ara tablo OK2(OgrenciId, KursId) = (1,1), (1,2).

SorguSonuçSatır
Ogrenci LEFT JOIN OK2 … LEFT JOIN Kurs …Ali–C#, Ali–SQL, Ayse–NULL3
Ogrenci JOIN OK2 … RIGHT JOIN Kurs …Ali–C#, Ali–SQL, NULL–Python3
Ogrenci LEFT JOIN OK2 … FULL JOIN Kurs …Ali–C#, Ali–SQL, Ayse–NULL, NULL–Python4

LEFT JOIN zincirinin ortasına bir INNER JOIN (ya da sağ tabloya WHERE koşulu) girerse soldaki eşsiz satırlar yine düşer.

COUNT ve LEFT JOIN

SELECT o.Ad, COUNT(k.Kurs) AS KursSayisi, COUNT(*) AS SatirSayisi
FROM Ogrenci o LEFT JOIN OgrenciKurs k ON k.OgrenciId = o.Id
GROUP BY o.Ad;
-- Ali  2  2
-- Ayse 0  1

"Kurs sayısı" için COUNT(*) Ayse'ye 1 verir; COUNT(sag.kolon) NULL'ı saymaz → 0.

Alıştırmalar: kaç satır gelir? Ölçüldü

WHERE Dept='IK' OR Dept='IT' AND Maas>8000 örnek veride 4 satır, (Dept='IK' OR Dept='IT') AND Maas>8000 2 satır döndürür Ölçüldü. Parantez koy.

NULL mantığı

  • Üç değerli mantık: TRUE / FALSE / UNKNOWN. NULL = NULL → NULL (bilinmez); WHERE yalnız TRUE'yu geçirir.
  • COUNT(*) vs COUNT(kolon): COUNT(*) bütün satırları, COUNT(kolon) NULL olmayanları, COUNT(DISTINCT kolon) farklı NULL-dışı değerleri sayar. 5 çalışan, biri yöneticisiz → COUNT(*) = 5, COUNT(YoneticiId) = 4.
  • Toplama fonksiyonları NULL'ı atlar: AVG(kolon) NULL'ları paydaya katmaz.
  • NULL ile aritmetik/birleştirme NULL verir: 'abc' || NULL → NULL.

NOT IN + NULL tuzağı

Alt sorgu tek bir NULL döndürürse x NOT IN (…) hiçbir satırda TRUE olmaz → 0 satır. "Yönetici olmayan çalışanlar" sorusu NOT IN (SELECT YoneticiId FROM Calisan) ile 0, NOT EXISTS ile 3 satır döndü Ölçüldü Resmî. Çözüm: NOT EXISTS ya da alt sorguya WHERE YoneticiId IS NOT NULL.

§ 4Gruplama

GROUP BY satırları gruplar; toplama fonksiyonları COUNT, SUM, AVG, MIN, MAX. WHERE gruplamadan önce satırı, HAVING sonra grubu süzer.

SELECT Dept, COUNT(*) AS Kisi, AVG(Maas) AS Ort
FROM Calisan
WHERE Maas > 0              -- satır süzgeci
GROUP BY Dept
HAVING COUNT(*) > 2;        -- grup süzgeci; WHERE COUNT(*) > 2 hatadır

SELECT'teki her kolon ya GROUP BY'da ya da bir toplama fonksiyonunun içinde olmalı. SELECT Dept, Ad, MAX(Maas) … GROUP BY Dept PostgreSQL ve SQL Server'da hata, MySQL'de ONLY_FULL_GROUP_BY açıkken hata verir. SQLite kabul eder ("bare column") ama eşitlikte yalnız bir kişiyi gösterir Ölçüldü. Bunun yerine window fonksiyonu ya da alt sorgu yaz.

Tamsayı bölmesi: 5/2 = 2 (SQLite, PostgreSQL, SQL Server); oran için 5 * 1.0 / 2 ya da CAST. MySQL'de / ondalık verir.

§ 5Alt sorgu, EXISTS, CTE, CASE

  • Skaler alt sorgu: tek değer döner — WHERE Maas > (SELECT AVG(Maas) FROM Calisan).
  • IN vs EXISTS: IN değer listesine, EXISTS "en az bir satır var mı"ya bakar ve NULL'dan etkilenmez. İyileştiriciler çoğu zaman ikisini aynı plana çevirir; asıl fark NOT IN + NULL'da.
  • Korelasyonlu alt sorgu: dıştaki satıra bağlıdır, mantıksal olarak her satır için yeniden çalışır.
  • CTE (WITH): adlandırılmış geçici sonuç; okunabilirlik. WITH RECURSIVE ağaç/hiyerarşi için.
  • CASE WHEN: koşullu değer; ilk doğru dalda durur, ELSE yoksa NULL.
-- Korelasyonlu: departmanının en yükseğini alanlar
SELECT Dept, Ad, Maas FROM Calisan c
WHERE Maas = (SELECT MAX(Maas) FROM Calisan x WHERE x.Dept = c.Dept);

-- CTE: departman ortalamasından fazla alanlar
WITH DeptOrt AS (SELECT Dept, AVG(Maas) AS Ort FROM Calisan GROUP BY Dept)
SELECT c.Ad FROM Calisan c JOIN DeptOrt d ON d.Dept = c.Dept WHERE c.Maas > d.Ort;

-- CASE: seviye ve koşullu sayım
SELECT Ad, CASE WHEN Maas >= 9000 THEN 'yuksek'
                WHEN Maas >= 7000 THEN 'orta'
                ELSE 'dusuk' END AS Seviye
FROM Calisan;
SELECT SUM(CASE WHEN Maas > 8000 THEN 1 ELSE 0 END) AS YuksekSayisi FROM Calisan;

CASE dallarının sırası önemli: WHEN Maas >= 7000 önce yazılırsa 9000 alan da "orta" olur.

  • Aynı tablo kendisiyle: UNION → 2 departman, UNION ALL → 10 satır Ölçüldü.

§ 7Window fonksiyonları

Satırları gruplamadan yanlarına grup bilgisi ekler: fonksiyon() OVER (PARTITION BY … ORDER BY …).

ORDER BY Maas DESC · Ölçüldü
AdMaasROW_NUMBERRANKDENSE_RANK
A9000111
E9000211
B7000332
C7000432

  • ROW_NUMBER: hep benzersiz 1, 2, 3… (eşitlikte sıra belirsiz → ikinci sıralama kolonu ekle).
  • RANK: eşitler aynı numara, sonra boşluk (1, 1, 3).
  • DENSE_RANK: eşitler aynı numara, boşluksuz (1, 1, 2) — "N. en yüksek farklı değer" için.
  • PARTITION BY: numaralamayı grup başına sıfırlar.
  • LAG(kolon) / LEAD(kolon): önceki / sonraki satırın değeri (ilk satırda NULL).
  • SUM(Maas) OVER (PARTITION BY Dept): her satırın yanında departman toplamı; SUM(x) OVER (ORDER BY Tarih): kümülatif toplam; AVG(x) OVER (…) aynı mantık.

Window fonksiyonu WHERE'de kullanılamaz (SELECT adımında hesaplanır) → alt sorgu/CTE içine al, dışarıda süz. GROUP BY satır sayısını azaltır, OVER azaltmaz.

§ 8Klasik mülakat soruları Mülakatta sık

Örnek tablo (hayalî veri): Calisan(Id, Ad, YoneticiId, Dept, Maas) — A 9000 IT · B 7000 IT · C 7000 IK · D 5000 IK · E 9000 IT. Sonuçların hepsi Ölçüldü.

İkinci en yüksek maaş (üç yol → 7000)

-- 1) Alt sorgu + MAX (her lehçede çalışır; ikinci yoksa NULL döner)
SELECT MAX(Maas) FROM Calisan WHERE Maas < (SELECT MAX(Maas) FROM Calisan);

-- 2) DISTINCT + LIMIT/OFFSET (SQLite, PostgreSQL, MySQL)
SELECT DISTINCT Maas FROM Calisan ORDER BY Maas DESC LIMIT 1 OFFSET 1;
--    SQL Server: ... ORDER BY Maas DESC OFFSET 1 ROWS FETCH NEXT 1 ROWS ONLY;

-- 3) DENSE_RANK
SELECT DISTINCT Maas FROM (
  SELECT Maas, DENSE_RANK() OVER (ORDER BY Maas DESC) AS r FROM Calisan
) t WHERE r = 2;

2. yolda DISTINCT unutulursa iki kişi 9000 aldığı için yine 9000 gelir.

N. en yüksek maaş

-- DENSE_RANK ... WHERE r = N   ya da   DISTINCT ... LIMIT 1 OFFSET N-1
SELECT DISTINCT Maas FROM Calisan c1
WHERE 2 = (SELECT COUNT(DISTINCT Maas) FROM Calisan c2 WHERE c2.Maas >= c1.Maas);   -- N = 2

Tekrar eden kayıtları bul ve sil

SELECT Eposta, COUNT(*) FROM Musteri GROUP BY Eposta HAVING COUNT(*) > 1;

-- Her gruptan en küçük Id kalsın (a, b, a, c, a → 3 satır kalır)
DELETE FROM Musteri
WHERE Id NOT IN (SELECT MIN(Id) FROM Musteri GROUP BY Eposta);

Burada NOT IN güvenli, çünkü MIN(Id) NULL olamaz. Alternatif: ROW_NUMBER() OVER (PARTITION BY Eposta ORDER BY Id) > 1 olanları sil. MySQL aynı tabloyu alt sorguda okuyup silmeye izin vermez; alt sorguyu bir kat türetilmiş tabloya sar.

Departman başına en yüksek maaşlı kişi

SELECT Dept, Ad, Maas FROM (
  SELECT *, RANK() OVER (PARTITION BY Dept ORDER BY Maas DESC) AS r FROM Calisan
) t WHERE r = 1;
-- IK–C, IT–A, IT–E → 3 satır (IT'de eşitlik). Tek kişi istenirse ROW_NUMBER.

Hiç sipariş vermeyen müşteriler

SELECT m.* FROM Musteri m
LEFT JOIN Siparis s ON s.MusteriId = m.Id
WHERE s.Id IS NULL;
-- ya da: WHERE NOT EXISTS (SELECT 1 FROM Siparis s WHERE s.MusteriId = m.Id)

Çalışan – yönetici

-- Yöneticisinden fazla kazananlar
SELECT c.Ad FROM Calisan c
JOIN Calisan y ON y.Id = c.YoneticiId
WHERE c.Maas > y.Maas;

Her gruptan ilk kayıt

SELECT * FROM (
  SELECT *, ROW_NUMBER() OVER (PARTITION BY Dept ORDER BY Id) AS rn FROM Calisan
) t WHERE rn = 1;            -- IK–C, IT–A; "son kayıt" için ORDER BY Id DESC

§ 9Veri değiştirme

INSERT INTO Calisan (Ad, Dept, Maas) VALUES ('F', 'IT', 6000);   -- kolon listesini yaz
INSERT INTO Arsiv (Ad) SELECT Ad FROM Calisan WHERE Maas < 6000;
UPDATE Calisan SET Maas = Maas + 5 WHERE Id = 1;                 -- aritmetik: kolon = kolon + 5
DELETE FROM Calisan WHERE Id = 4;

§ 10Şema, kısıtlar, normalizasyon, index

AnahtarKısaca

  • 1NF: her hücrede tek (atomik) değer, tekrar eden grup yok. 2NF: 1NF + bileşik anahtarın bir kısmına bağlı kolon yok. 3NF: 2NF + anahtar olmayan kolona bağlı kolon yok (geçişli bağımlılık yok). Kısaca: "anahtara, anahtarın tamamına, anahtardan başka hiçbir şeye."
  • Denormalizasyon: okuma hızı için bilinçli tekrar (raporlama).
  • Index: WHERE / JOIN / ORDER BY'da sık kullanılan, seçici kolonlarda okumayı hızlandırır; her INSERT/UPDATE/DELETE'te güncellendiği için yazmayı yavaşlatır, yer kaplar. Kolonu fonksiyona sokmak (UPPER(Ad) = …) ya da başta joker (LIKE '%abc') çoğu zaman index'i kullanamaz. Bileşik index'te soldan sağa sıra önemli.
  • Clustered vs nonclustered (SQL Server): clustered = verinin kendisi o anahtara göre sıralı tutulur, tabloda bir tane; nonclustered = ayrı yapı, satıra işaret eder, birden çok olabilir.
  • View: kaydedilmiş SELECT; veri tutmaz (materialized view hariç); sadeleştirme ve yetki için.

SQLite'ta yabancı anahtar denetimi varsayılan kapalıdır; her bağlantıda PRAGMA foreign_keys = ON; Resmî.

§ 11Transaction, ACID, izolasyon

BEGIN → işlemler → COMMIT (kalıcı) ya da ROLLBACK (geri al); SAVEPOINT ile ara nokta. ACID: Atomicity (ya hepsi ya hiçbiri) · Consistency (kısıtlar korunur) · Isolation (eşzamanlı işler birbirini bozmaz) · Durability (commit edilen kalıcı).

SeviyeDirty readNon-repeatable readPhantom read
Read UncommittedOlabilirOlabilirOlabilir
Read CommittedYokOlabilirOlabilir
Repeatable ReadYokYokOlabilir
SerializableYokYokYok
  • Dirty read: başkasının commit etmediği veriyi okumak. Non-repeatable: aynı satırı iki kez okuyunca farklı değer. Phantom: aynı koşulla tekrar sorgulayınca yeni satır belirmesi.
  • Varsayılanlar Resmî: PostgreSQL ve SQL Server Read Committed; MySQL InnoDB Repeatable Read. PostgreSQL'de Read Uncommitted, Read Committed gibi davranır ve Repeatable Read'de phantom da oluşmaz. SQL Server'da ek olarak SNAPSHOT seviyesi vardır.

§ 14Mülakat günü kontrol listesi (online test)

Bu liste otomatik değerlendirilen online SQL testi içindir. Canlı ya da yüz yüze mülakatta platforma özgü maddeler (3, 7, 8, 9) gerekmeyebilir; diğer mülakat türleri için kardeş rehber: Mülakat Hazırlığı.

  1. Şemayı ve örnek çıktıyı dikkatle oku: kolon adları, sırası, alias'lar birebir aynı olmalı.
  2. Büyük/küçük harf ve boşluk: metin karşılaştırmaları ve çıktı başlıkları.
  3. Her komutun sonuna ;.
  4. İstenen sırayı koru; ORDER BY istenmişse yaz, eşitlik için ikinci kolon ekle.
  5. Örnek veri ≠ tam veri: sabit Id'ye göre değil koşula göre yaz; gizli testler farklı veriyle çalışır.
  6. NULL, eşitlik (aynı maaş), boş tablo, tekrar eden değer durumlarını düşün.
  7. UPDATE/DELETE görevinde istenmeyen fazladan SELECT ekleme.
  8. Testleri çalıştır, hata mesajını oku: near "X" = hata X'in hemen önünde.
  9. Motor ya da sürüm belirsizse sorgula (§ 12): SQLite SELECT sqlite_version(); · PostgreSQL SELECT version(); · MySQL SELECT VERSION(); · SQL Server SELECT @@VERSION;. SQLite 3.39.0'dan eskiyse RIGHT/FULL JOIN yerine LEFT ile yaz.
  10. Süre kalırsa okunabilirlik: CTE, anlamlı alias, girintili yazım.

§ 15Hızlı tekrar (cheat sheet)

  • Çalışma sırası: FROM/JOIN → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → LIMIT.
  • INNER = eşleşenler · LEFT ≥ sol satır · RIGHT ≥ sağ satır · FULL = LEFT ∪ RIGHT · CROSS = a×b.
  • LEFT JOIN = LEFT OUTER JOIN; JOIN = INNER JOIN.
  • Çoklu eşleşme çoğaltır (2 × 3 = 6). NULL anahtar eşleşmez.
  • Anti-join: LEFT JOIN … WHERE sag.anahtar IS NULL ya da NOT EXISTS.
  • Sağ tablo koşulu ON'a; WHERE'e yazarsan LEFT → INNER olur.
  • = NULL değil IS NULL. NOT IN + NULL = boş sonuç → NOT EXISTS.
  • COUNT(*) satır, COUNT(kolon) NULL-dışı sayar.
  • BETWEEN uçlar dahil. AND önce bağlar — parantez koy.
  • WHERE satır, HAVING grup süzer; window fonksiyonu WHERE'de olmaz.
  • ROW_NUMBER 1,2,3 · RANK 1,1,3 · DENSE_RANK 1,1,2.
  • 2. en yüksek: MAX … WHERE x < MAX · DISTINCT … LIMIT 1 OFFSET 1 · DENSE_RANK = 2.
  • Grup başına en iyi: RANK() OVER (PARTITION BY g ORDER BY x DESC) = 1.
  • Tekrar sil: DELETE … WHERE Id NOT IN (SELECT MIN(Id) … GROUP BY k).
  • UNION tekrarı atar, UNION ALL atmaz.
  • DELETE (satır, WHERE) · TRUNCATE (hepsi, hızlı, SQLite'ta yok) · DROP (tablo gider).
  • UPDATE/DELETE'ten önce aynı WHERE ile SELECT.
  • ACID; varsayılan Read Committed (PostgreSQL, SQL Server), Repeatable Read (MySQL InnoDB).
  • SQLite: ; · RIGHT/FULL ≥ 3.39.0 · UPDATE FROM ≥ 3.33.0 · window ≥ 3.25.0 · || · LIMIT · PRAGMA foreign_keys = ON.
  • 5/2 = 2 → 5 * 1.0 / 2.
