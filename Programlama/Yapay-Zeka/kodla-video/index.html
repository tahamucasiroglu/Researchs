Remotion ve kodla video: kısa başvuru

Video = kare numarasının fonksiyonu. Remotion bunu React ile yapar. Bu sayfada nasıl çalıştığı, yapay zekâyla kullanımı, lisansı, yerel model seçenekleri ve alternatifleri var.

§ 2Remotion nedir, nasıl çalışır

Remotion, videoyu React bileşeni olarak yazdıran bir TypeScript çatısıdır. Bileşen her kare için yeniden çizilir; useCurrentFrame() o anki kare numarasını, useVideoConfig() genişlik, yükseklik, fps ve süreyi verir. Animasyon, kare numarasından değer hesaplamaktır (interpolate, spring). Bileşen <Composition> ile kaydedilir; render sırasında başsız Chrome her kareyi açar, ekran görüntüsünü alır ve FFmpeg bunları videoya kodlar.

  1. React bileşeni — kareye bağlı JSX (yazı, SVG, görsel, video, ses).
  2. Kareler — başsız Chrome her kareyi çizer. Varsayılan JPEG; saydamlık gerekirse PNG.
  3. Kodlama — FFmpeg kareleri birleştirir. 4.0.534'ten beri "paralel kodlama" varsayılan: Chrome sonraki kareleri çizerken FFmpeg öncekileri kodlar (bedeli: daha yüksek tepe bellek).
  4. Paralellik — concurrency varsayılanı CPU iş parçacıklarının yarısı.

§ 4En kısa örnek

src/Baslik.tsx

import {AbsoluteFill, interpolate, useCurrentFrame} from 'remotion';

export const Baslik: React.FC<{metin: string}> = ({metin}) => {
  const kare = useCurrentFrame();
  const opaklik = interpolate(kare, [0, 30], [0, 1], {extrapolateRight: 'clamp'});
  return (
    <AbsoluteFill style={{background: '#111', justifyContent: 'center', alignItems: 'center'}}>
      <h1 style={{color: 'white', fontSize: 90, opacity: opaklik}}>{metin}</h1>
    </AbsoluteFill>
  );
};

src/Root.tsx

import {Composition} from 'remotion';
import {Baslik} from './Baslik';

export const RemotionRoot = () => (
  <Composition
    id="Baslik"
    component={Baslik}
    durationInFrames={90}   // 3 sn @ 30 fps
    fps={30}
    width={1080}
    height={1920}           // dikey video
    defaultProps={{metin: 'Merhaba'}}
  />
);

Render

npx create-video@latest               # yeni proje
npx remotion studio                    # önizleme
npx remotion render Baslik out/baslik.mp4 --props='{"metin":"Tarih videosu"}'

§ 6Yerel LLM ile: mümkün olan / olmayan

Küçük model (4–9B) yapar

  • Düz bir şemaya uyan sahne JSON'u (metin, süre, sahne türü, renk).
  • Verilen kaynak metni özetlemek / çevirmek.
  • Ollama format alanına JSON şeması verilir; sıcaklık 0 önerilir.

Küçük model zayıf

  • Her video için yeni React/TSX yazmak: interpolate aralıkları, SVG yolları, kare zamanlaması bozulur TAHMİN.
  • Kaynaksız tarih/isim/rakam: uydurma riski yüksek.
  • Uzun istem + şema 4K bağlamı aşınca kuralları sessizce unutma.

Doğru mimari: TSX sahne türleri (başlık, harita, zaman çizelgesi, karşılaştırma, alıntı…) bir kez yazılır. Composition'a Zod şeması bağlanır; LLM yalnız bu şemaya uyan sahne listesini üretir. Aynı şema hem Ollama format'ında hem Remotion doğrulamasında kullanılır.

Örnek sahne JSON'u (genel tarih videosu)

{
  "sahneler": [
    {"tur": "baslik", "metin": "Antik yapıların sırrı", "sure_sn": 4, "renk": "#c8a24a"},
    {"tur": "alinti", "metin": "…", "kaynak_alinti": "kaynak metinden birebir cümle", "sure_sn": 6},
    {"tur": "zaman_cizelgesi", "olaylar": [{"yil": "MÖ 27", "metin": "…"}], "sure_sn": 8}
  ]
}
  • Uydurmaya karşı ÖNERİ: kaynak metni (ör. Wikipedia) kod çeker ve isteme verir; her sahnede zorunlu kaynak_alinti; kod alıntının kaynakta birebir geçtiğini dize aramasıyla denetler, geçmeyen sahne reddedilir.
  • Biçim ≠ içerik: şema kısıtı biçimi garanti eder; alanların anlamı istemde tarif edilmezse model en kısa geçerli değeri yazar. Karmaşık iç içe şema küçük modelde kaliteyi düşürür.
  • Ollama bağlamı: 24 GiB'tan küçük kartlarda varsayılan 4K token. num_ctx / OLLAMA_CONTEXT_LENGTH ile elle büyüt (VRAM artar).
  • Hata: düşünme kipi kapalıyken Qwen3.5/Gemma 4'te format yok sayılıyordu; Gemma 4 için Ollama v0.21.1, Qwen3.5 için v0.31.2'de düzeldi.

§ 10Kendi çizicini yazmak (Skia + FFmpeg)

Remotion'un yaptığı iş özünde "her kareyi çiz → FFmpeg'e ver"dir. Uygulama zaten bir 2B çizim kütüphanesi (Skia/SkiaSharp vb.) ve FFmpeg kullanıyorsa, kareler bellekten doğrudan FFmpeg'e (-f rawvideo → stdin) verilebilir; Chrome ve ekran görüntüsü adımı olmaz.

Artıları

  • Node, Chrome, render ücreti, telemetri yok; tamamen çevrimdışı; lisans temiz.
  • Kurulum boyutu küçük kalır (Chrome paketlenmez).
  • 2B vektör sahnelerde Chrome'dan hızlı olması beklenir TAHMİN (ölçülmedi).
  • Lottie: SkiaSharp.Skottie (MIT) aynı tuvale çizer.

Eksileri

  • Düzen (flexbox benzeri), metin kaydırma/ölçme, easing/spring, SVG yolu animasyonu, maske/bulanıklık/gölge elle yazılır.
  • Remotion ekosistemi (haritalar, Three.js, Code Hike…) yok.
  • Animasyon kalitesi senin yazdığın kalıplar kadar.
  • Skottie AE ifadelerini ve bazı efektleri desteklemeyebilir TAHMİN.

LLM'e kod yerine JSON sahne tarifi yazdırmak: kod çalıştırılmaz, yalnız şemaya karşı doğrulanan veri okunur (kum havuzu gerekmez). Remotion lisansının yasakladığı "kullanıcının kendi kodunu render ettirmesi" durumu da tümden ortadan kalkar. Bedeli: yeni bir görsel fikir için kalıbı geliştiricinin eklemesi gerekir.
