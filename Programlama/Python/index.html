Python: anahtar liste

Dil temellerinden NumPy, Pandas, TensorFlow ve OpenCV'ye, web çatılarından test araçlarına kadar Python ekosisteminde aranacak terimler. İş ilanlarında ve mülakatlarda sık geçen konular ayrıca işaretli.

Seviye: temel → orta · Rozetler iş/mülakat önceliğine göre; başka hedefler için okuma notu § 1'de

§ 1Bu sayfa nasıl kullanılır

Burası anlatım sayfası değil, arama listesi. Her satır bir terim, yanında bir-iki cümlelik "bu nedir" notu ve mümkünse resmî doküman bağlantısı. Konuyu buradan öğrenmeyeceksin; buradan neyi arayacağını öğrenip kendi kaynağından okuyacak ve kod yazacaksın.

Rozetleri öncelik sırası olarak oku: MÜLAKATTA SIK iş ilanlarında ve mülakatlarda sık geçen; en az bir çalışan örnek yaz; TEMEL bu alanda olmazsa olmaz, önce bu; ORTA sonra gelir; İLERİ derinleşme, acele etme; ÜCRETLİ lisansı para ister; ESKİMİŞ hâlâ karşına çıkar ama yeni projede kullanma.

Mülakatta her anahtar kelime bir soru başlığıdır

Python ilanlarında sık geçen başlıklar alana göre değişir: veri tarafında NumPy, Pandas, scikit-learn; yapay zeka tarafında TensorFlow / PyTorch; backend tarafında FastAPI, Django, SQLAlchemy; otomasyon tarafında web scraping; dil bilgisi olarak fonksiyonel programlama, eşzamanlılık, test. Bunların her biri mülakatta ayrı bir soru başlığıdır ve hiçbiri "biraz baktım" cevabıyla geçilmez. Bir makine öğrenmesi projesi anlatıyorsan mülakatçı ilk oraya yönelir: "hangi mimari?", "veri setini nasıl böldün?", "overfit oldu mu, nereden anladın?". Hedeflediğin ilandaki başlıklar için önce bu sayfadaki MÜLAKATTA SIK satırlarına çalış.

Hedefin iş mülakatı değilse rozetleri böyle oku

  • İş / mülakat hedefi → rozetler yazıldığı gibi geçerli.
  • Akademik çalışma / araştırma, veri analizi, otomasyon veya hobi → MÜLAKATTA SIK rozetini "sahada yaygın kullanılan" diye oku; öncelik, kendi işinde ihtiyaç duyduğun alandır (ör. araştırmacı için NumPy/Pandas/görselleştirme, otomasyon için § 7 ve § 21).
  • Öğrenci veya yeni başlayan → önce TEMEL rozetli satırlardan başla; ilan başlıklarını sonraya bırak.

Bu sayfa sadece Python. Diğer diller kendi bölümlerinde: Go, Rust, C# / .NET, JavaScript/TypeScript tarafı için JavaScript / TypeScript bölümü, kurumsal muadili için Java bölümü, tüm haritanın üstü için ana sayfa.

Python'u başka bir dil bilerek öğrenmek kolaydır; tehlikeli olan da budur. Sözdizimi bir günde oturur, sonra uzun süre seni ısıranlar, geldiğin dilin alışkanlıklarıdır.

Sürüm notu

Free-threaded (GIL'siz) build (PEP 703) sürüme göre farklıdır:

  • 3.12 ve öncesi → free-threaded build yoktur.
  • 3.13 → deneysel, ayrı bir build olarak sunuldu (python3.13t).
  • 3.14 → PEP 779 ile resmî olarak destekleniyor, ama hâlâ opsiyonel; varsayılan değil.

Mülakatta "GIL kalktı mı?" sorusuna cevabın: "Varsayılan yorumlayıcıda her sürümde hâlâ var; 3.13'te deneysel, 3.14'te desteklenen ayrı bir free-threaded build olarak sunuluyor." Bkz. whatsnew 3.13 ve 3.14.

§ 6Tip ipuçları (type hints)

Python dinamik tiplidir: değişkenin tipi çalışma anında belirlenir. Bunun sana etkisi geldiğin dile bağlıdır:

  • C# / Java gibi statik tipli bir dilden → Python'un en rahatsız edici tarafı tipsizliktir; type hints + mypy ile disiplini geri getirirsin.
  • TypeScript'ten → kavram çok tanıdık: TS tipleri gibi Python tipleri de çalışma zamanında zorlanmaz, denetimi araç yapar.
  • JavaScript / Ruby'den → tipsizlik tanıdıktır; tip ipuçları ek bir kazançtır.
  • Hiç programlama bilmiyorsan → bu bölümü dil temellerinden (§ 2-§ 5) sonra oku.

İyi haber: 3.5'ten beri isteğe bağlı tip bildirimi var ve modern kütüphanelerin (FastAPI, Pydantic, SQLAlchemy 2.0) tamamı buna dayanıyor. Kötü haber: bunlar çalışma zamanında zorlanmaz, sadece mypy gibi bir denetleyici okur.

§ 8Eşzamanlılık: threading, multiprocessing, asyncio

Dikkat — başka dilden gelenin en büyük yanılgısı

Standart (GIL'li) Python yorumlayıcısında GIL (Global Interpreter Lock) yüzünden thread'ler CPU işini paralelleştiremez. CPU işi için multiprocessing, I/O işi için threading veya asyncio kullanılır. Bu ayrımı bilmemek Python mülakatında en görünür eksiktir.

  • C# / Java'dan geliyorsan → Task.Run / thread havuzuyla CPU işini paralelleştirme sezgin burada çalışmaz.
  • Node.js'ten geliyorsan → asyncio olay döngüsü tanıdıktır; CPU işinde worker_threads yerine multiprocessing düşün.
  • Go'dan geliyorsan → goroutine gibi çekirdeklere otomatik yayılan paralellik yoktur.
  • Free-threaded build kullanıyorsan (3.13 deneysel, 3.14 destekli) → threading ile CPU paralelliği mümkündür; ancak kullandığın C eklentilerinin (NumPy vb.) bu build ile uyumlu olması gerekir TEYİT py-free-threading.github.io uyumluluk listesi.

  • Veri hazırlama — ham veriyi nasıl temizledin? (Görüntüde: videodan kare çıkarma, ilgi bölgesini kırpma; tabloda: eksik değer, aykırı değer; metinde: temizleme, tokenizasyon)
  • Bölme stratejisi — train/val/test oranı; aynı kaynağa ait örneklerin iki kümede birden olmamasını nasıl sağladın?
  • Ön işleme — yeniden boyutlandırma (kaça?), normalizasyon (0-1 mi, ImageNet ortalaması mı?)
  • Veri artırma — hangi dönüşümler, neden? Görevine bağlıdır: doğal fotoğraflarda yatay çevirme genelde uygun, dikey çevirme genelde değil; uydu ve mikroskopi görüntülerinde dikey çevirme ve döndürme de uygundur; yazı/rakam gibi yönü anlam taşıyan görüntülerde çevirme etiketi bozabilir
  • Model mimarisi — sıfırdan CNN mi, transfer learning mi? Hangi omurga (ResNet, EfficientNet, MobileNet)?
  • Katman listesi — kaç Conv2D, hangi aktivasyon, dropout oranı, son katman (görev türüne göre; yukarıdaki tabloya bak — ikili sınıflandırmada 1 nöron + sigmoid)
  • Eğitim ayarları — loss (görev türüne göre; ikili sınıflandırmada binary crossentropy), optimizer (Adam), learning rate, batch size, epoch sayısı
  • Overfitting — oldu mu? Nereden anladın (eğitim/doğrulama kaybı eğrisi)? Ne yaptın (EarlyStopping, dropout, augmentation)?
  • Metrikler — sadece accuracy söyleme; sınıflandırmada precision, recall, F1, ROC AUC ve confusion matrix, regresyonda RMSE, MAE, R² ver
  • Hata analizi — model en çok neyi karıştırdı? Düşük çözünürlük, sıkıştırma artefaktı, aydınlatma?
  • Genelleme — eğitim verisinden farklı kaynaktan gelen veride başarım düştü mü? (Çoğu görüntü modelinin bilinen zayıflığı)
  • Donanım ve süre — hangi donanım (NVIDIA GPU + CUDA, Apple Silicon + MPS, CPU, Colab/Kaggle gibi bulut GPU'su), eğitim ne kadar sürdü?
  • Sonraki adım — bugün yeniden yapsan neyi değiştirirdin? (Bu soruya hazır cevabı olan aday öne çıkar)

FastAPI = tip tabanlı, hafif, otomatik Swagger üreten API çatısı. Django = ORM, admin paneli, kimlik doğrulama, migration dahil tam paket. Flask = çıplak, her şeyi sen eklersin. Üçü de ücretsiz açık kaynak.

  • ASP.NET Core'dan → FastAPI = Minimal API'ye en yakın olan; Django = ASP.NET Core MVC + EF Core + Identity'nin tek kutuda hali.
  • Java / Spring Boot'tan → Django = Spring Boot'un "her şey dahil" yaklaşımına yakın; FastAPI = daha hafif bir Spring WebFlux / Micronaut hissi.
  • Node / Express'ten → Flask ≈ Express; FastAPI ≈ tipli Express / NestJS.
  • Hiç web çatısı bilmiyorsan → küçük bir API için FastAPI; admin paneli ve kimlik doğrulaması hazır tam site için Django; en sade öğrenme için Flask.

§ 21Otomasyon ve web scraping

Beklenen cevaplar: requests ile sayfayı çekip BeautifulSoup ile ayrıştırmak; JavaScript ile üretilen içerik için Selenium veya Playwright kullanmak; çok sayfalı, kuyruklu iş için Scrapy. Yasal/etik sınır, toplanan veriye göre değişir (hukuki görüş değildir):

  • Site resmî bir API sunuyorsa → scraping yerine API tercih edilir.
  • Kişisel veri içeren sayfalar → Türkiye'de KVKK (6698 sayılı Kanun), AB'de GDPR kapsamına girer; açık rıza veya başka bir hukuki dayanak gerekebilir TEYİT kvkk.gov.tr.
  • Kişisel olmayan, kamuya açık veri → sitenin kullanım koşulları + robots.txt + hız sınırı gözetilir.
  • Veri tabanının veya içeriğin toplu kopyalanması → Türkiye'de FSEK (5846 sayılı Kanun) kapsamındaki eser ve veri tabanı hakları gündeme gelir TEYİT mevzuat.gov.tr.

§ 23Test ve kod kalitesi

İyi haber: Python'da mock yazmak statik tipli dillerden kolaydır (arayüz gerekmez, patch ile doğrudan değiştirirsin). Kavramlar her dilde aynıdır: stub, mock, fake, spy, arrange-act-assert.   • JavaScript / TypeScript → Jest veya Vitest mock'ları
  • Python tek / ana dilinse → yalnızca pytest + unittest.mock yeterli.
