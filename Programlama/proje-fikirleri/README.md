# Proje Fikirleri

Okumak bir konuyu öğrendiğini göstermez; her başlığın karşılığında yazılmış, çalışan kod olmalıdır. Bu sayfa bir öğretici değil, **proje kataloğudur**: küçük tek dosyalık denemelerden portfolyoya konabilecek tam projelere kadar fikirleri, her birinin kapsamını, zorluğunu ve hangi teknolojiyi kanıtladığını listeler. Teknolojilerin nasıl öğrenileceği dil bölümlerindedir; burada yalnızca "ne yapayım" sorusunun cevabı vardır.

Önerilen yol deneyime göre değişir:

- **Hiç kod yazmamışsan:** önce seçtiğin dilin bölümündeki temel başlıklar (bu sayfa dil öğretmez), sonra tek dosyalık denemeler.
- **Dili biliyor ama altyapı deneyimin yoksa:** tek dosyalık denemelerle bir kavramı kendi elinle çalıştır, küçük projelerle onu gerçek altyapıya (veritabanı, kuyruk, önbellek) bağla, orta projelerle birleştir, sonunda mülakatta ekran paylaşımıyla gösterilebilecek bir portfolyo projesi çıkar.
- **Deneyimliysen:** doğrudan orta projelere veya portfolyo projesine geç.

Proje tarifleri çoğunlukla C#/.NET araçlarıyla yazıldı; Java, Node.js, Python ve Go karşılıkları sayfadaki eşleştirme tablolarında verilir. Frontend, mobil veya veri hedefleyen okur için ilgili orta projeler ve profil bazlı öncelik tablosu da sayfada yer alır.

Temel kurallar: bir proje tek bir şeyi kanıtlamalı, bitmiş küçük proje yarım büyük projeden değerlidir, README ilk gün yazılır ve proje tek komutla çalışabilmelidir — altyapı bağımlılığı olan backend projesinde `docker compose up`, statik arayüzde `npm install && npm run dev` veya yayınlanmış bir GitHub Pages bağlantısı, CLI aracı veya kütüphanede tek komutla kurulum (`dotnet tool install`, `pip install`, `cargo install`).

## Sayfadaki başlıklar

1. Bu sayfa nasıl kullanılır (rozet sözlüğü, proje seçme kuralları)
2. A) Tek dosyalık denemeler (1–2 saat)
3. B) Küçük projeler (1–3 gün)
4. C) Orta projeler (1–2 hafta)
5. D) Portfolyo projeleri (2–4 hafta)
6. E) Projeyi "portfolyo kalitesine" çıkaran şeyler
7. F) Ne yapılmamalı
8. Özet — öncelik sırası
