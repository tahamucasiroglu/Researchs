Bölüm 03 · Veri ve Mimari

EF Core, Dapper ve veritabanı

ORM'in derinlikleri, ham SQL, migration stratejileri, sorgu performansı ve önbellekleme. Redis burada başlıyor.

Seviye: temel → ileri · Performans başlıkları ayrı

§ 1Bu sayfa nasıl kullanılır

Bu bir anlatım değil, arama listesi. Her satır bir başlık; onu kendin araştıracak, kendi kaynağından okuyacak ve kod yazacaksın. "Kısaca" sütunu sadece terimi tanıman için, "Not" sütunu önceliğini söylüyor.

İş arıyorsan sıra şu: önce MÜLAKATTA SIK rozetli satırlar (ilanlarda sık geçer, mülakatta bilmemek en pahalı senaryodur), sonra TEMEL, sonra ORTA, en son İLERİ. Veritabanına yeni başlıyorsan önce TEMEL satırlar; aşağıdaki tablo veri geçmişine göre nereden başlayacağını söyler.

Bir terimi aratırken tek başına arama; ön ek koy. Örnek: "migration" tek başına göç anlamına gelir, "EF Core migration" yaz. "Index" tek başına sayfa dizini getirir, "SQL Server clustered index" yaz.

Dikkat

Entity Framework Core, Dapper, Redis, PostgreSQL, MemoryCache ve Fluent API .NET ilanlarında sık geçen başlıklardır. Hangisinin senin için "az denenmiş" olduğu, veri geçmişine bağlıdır; önceliğini aşağıdaki tablodan al. SQL Server ve LINQ tarafını düzenli kullananlar için oradaki satırlar tekrar/derinleştirme amaçlıdır.

§ 3SQL Server ve T-SQL

.NET ilanlarının çoğunda istenen ve .NET projelerinde en yaygın kullanılan veritabanı. Bu bölümü kullanma biçimin SQL Server'la ilişkine bağlı:

  • SQL Server'ı günlük kullanıyorsan → Satırları tara, hiç dokunmadığın başlıkları işaretle.
  • Hiç kullanmadıysan → Önce kurulum: Windows → Developer veya Express sürümü + SSMS (ya da LocalDB). Linux → SQL Server for Linux'u desteklenen dağıtımlarda (RHEL, Ubuntu, SLES) paket yöneticisiyle (dnf/apt/zypper) doğrudan kur ya da Docker'da çalıştır; istemci olarak VS Code mssql eklentisi (desteklenen dağıtım ve sürümler için TEYİT: learn.microsoft.com SQL Server on Linux). macOS → yerel kurulum yok; Docker'da SQL Server (Apple Silicon Mac'te x64 emülasyonuyla) + VS Code mssql eklentisi; konteyner çalıştıramıyorsan uzak bir sunucuya veya Azure SQL'e bağlan. LocalDB yalnızca Windows'ta çalışır. Sonra T-SQL, index ve yedekleme satırlarını TEMEL olarak çalış.
  • PostgreSQL kullanıyorsan → Bu bölümü "ilanda SQL Server isteniyorsa" koşuluyla çalış; farklar için § 8.

§ 4EF Core — çekirdek kavramlar

Risk

"Entity Framework Core" .NET ilanlarının neredeyse hepsinde geçer. Mülakatta EF Core'dan en az üç soru gelir: change tracker nedir, N+1 problemi nedir, AsNoTracking ne yapar. Bu bölümdeki her satırı elinle kod yazarak geç.

§ 10Redis — derinlemesine

Risk

"Redis biliyorum" yazan ama "sadece duydum" diyen bir aday, tek soruda açığa çıkar. Klasik soru sırası: Redis nedir → hangi veri tiplerini kullandın → cache invalidation'ı nasıl yaptın → TTL nasıl belirlediniz. Docker ile bir Redis kaldır, StackExchange.Redis ile bağlan, hepsini elinle dene.

  • Öncelik → EF Core/SQL temeli oturmuş ve mülakata hazırlanıyorsan bu bölüm sayfanın en yüksek öncelikli bölümü. Veritabanı temelin yoksa önce § 2 ve § 4. Tek sunuculu küçük uygulamada önce IMemoryCache (§ 11); Redis'e çok sunucu veya paylaşılan önbellek gerektiğinde geç.
  • Platform → Linux/macOS: Docker veya yerel paket (apt, brew). Windows: Docker Desktop veya WSL içinde Redis; resmî yerel Windows sürümü yok, alternatif olarak Garnet (.NET ile yazılmış, Windows'ta yerel çalışır) veya Memurai.
  • Lisans → Redis 8 AGPLv3 / RSALv2 / SSPLv1 seçenekleriyle dağıtılır; daha serbest (BSD) lisans isteyen için Valkey (TEYİT: redis.io lisans sayfası).

§ 14Performans ve profilleme

§ 15Özet — bu sayfanın öncelik sırası

Bu sayfa için iki sıra var:

  • (A) Mülakata hazırlanan, SQL Server + EF Core deneyimli okur → Aşağıdaki numaralı liste. Sırayla git; üsttekiler mülakatta doğrudan sorulur, alttakiler "biliyorsan artı" seviyesidir.
  • (B) Sıfırdan öğrenen okur → § 2 SQL temelleri → § 3 veya § 8 (tek motor) → § 4 EF Core çekirdek → § 5 sorgulama / N+1 → § 6 migration → § 7 Dapper → § 11 IMemoryCache → § 10 Redis → § 12 desenler → § 14 profilleme → § 9 NoSQL.
  1. 1. Redis — sıfırdan pratik (§ 10)

    Docker ile Redis kaldır, redis-cli ile beş veri tipini dene, StackExchange.Redis ile bağlan, IDistributedCache ve HybridCache ile bir cache-aside örneği yaz. TTL, eviction policy ve cache stampede'i açıklayabilecek hale gel. (A) sırasında bu sayfadaki en yüksek öncelikli konu burası; temeli olmayan okur için (B) sırasındaki yerine bak.

    Mülakatta sık · pratikte az denenir · en çok sorulan
  2. 2. EF Core çekirdek + N+1 + AsNoTracking (§ 4, § 5)

    DbContext yaşam döngüsü, change tracker, entity states, Include/lazy loading farkı, N+1'in nasıl oluştuğu ve nasıl görüldüğü (ToQueryString/LogTo), projection ile çözümü. Sonra ExecuteUpdate/ExecuteDelete.

    Mülakatta sık · pratik eksikliği hemen fark edilir
  3. 3. EF Core migration hattı (§ 6)

    dotnet ef kur, add/update/script/--idempotent/bundle akışını uçtan uca çalıştır. Database.Migrate()'in hangi durumda kabul edilebilir, hangi durumda riskli olduğunu anlat (§ 6).

    İlanlarda "Migration" sık geçer
  4. 4. Dapper ve "ne zaman hangisi" (§ 7)

    Temel Query/Execute, parametreler, multi-mapping, QueryMultiple. Ardından EF Core ile birlikte kullanım stratejini bir paragrafta anlatabilecek hale gel.

    Mülakatta sık
  5. 5. Fluent API ve konfigürasyon (§ 4)

    IEntityTypeConfiguration ile ilişkileri, index'leri, value converter'ları elle kur. Global query filter ile soft delete + multi-tenant örneği yaz.

    İlanlarda "Fluent API" ve "Multi-Tenant" sık geçer
  6. 6. PostgreSQL'e ilk temas (§ 8)

    Geldiğin yere göre: SQL Server'dan geliyorsan Docker ile PostgreSQL kaldır, Npgsql sağlayıcısıyla aynı projeyi çalıştır, jsonb ve bir extension dene; "PostgreSQL kullandım" diyebilmek için minimum bu. PostgreSQL'den geliyorsan tersini yap: aynı projeyi SQL Server sağlayıcısıyla çalıştır, IDENTITY, collation ve datetimeoffset farklarını dene. Hiç motor bilmiyorsan tek motor seç; ikincisi sonra.

    Mülakatta sık · ilan sayısı yüksek
  7. 7. IMemoryCache ve cache stratejileri (§ 11)

    Absolute/sliding expiration, SizeLimit, output caching, ETag. IMemoryCache'in neden çok sunucuda yetmediğini anlat.

    İlanlarda "MemoryCache" sık geçer
  8. 8. SQL derinleştirme (§ 2, § 3)

    SQL'i günlük işte kullananlarda bile eksik kalanlar genelde: execution plan okuma, isolation level tablosu, window function, CTE, partitioning, Query Store (SQL Server; PostgreSQL'de karşılığı pg_stat_statements ve EXPLAIN). Bunlar mülakatta seni öne çıkarır. SQL'e yeni başlıyorsan bu adım (B) sırasında olduğu gibi başa gelir.

    Tekrar ve derinleştirme
  9. 9. Repository / UoW / Specification tartışması (§ 12)

    Generic repository yazmak zor değildir. Çoğu zaman eksik olan, "EF Core varken repository gerekli mi" sorusuna gerekçeli cevap. Devamı 04. sayfada.

    Kavramsal · kod değil tartışma sorusu
  10. 10. Profilleme araçları (§ 14)

    MiniProfiler, EF LogTo; SQL Server'da SET STATISTICS IO ve First Responder Kit, PostgreSQL'de EXPLAIN ANALYZE ve pg_stat_statements. Bir yavaş sorguyu bulup düzelttiğin somut bir hikâye hazırla.

    Performans iddiasını somutlaştırır
  11. 11. NoSQL farkındalığı (§ 9)

    Hedefe göre: hedef ilan/proje ilişkisel ağırlıklıysa MongoDB'nin ne olduğunu, ne zaman seçileceğini, CAP teoremini anlatabil; kod yazmasan da olur, kavram düzeyi yeterli. İlan MongoDB, Cosmos DB veya Elasticsearch istiyorsa resmî .NET sürücüsüyle CRUD ve aggregation/sorgu kodu yaz, şema tasarımını (gömme vs referans) çalış. Arama/log projesi → Elasticsearch/OpenSearch öne. Yapay zekâ / RAG projesi → vektör veritabanı (pgvector, Qdrant) öne.

    İlişkisel hedefte kavram düzeyi yeterli; NoSQL hedefinde kod düzeyi
  12. 12. Migration araçları ve ileri konular (§ 13)

    DbUp/FluentMigrator/Flyway farkını bil. Zero-downtime şema değişikliği kavramını oku. Acele etme.

    İleri · sonraya bırakılabilir
