Bölüm 03 · Kütüphane

React: bileşen, state ve hook'lar

Temel kavramlardan hook'ların tamamına, performans optimizasyonundan yaygın kalıplara. Her başlık bir araştırma sorgusu; sırayla ilerlemek için tasarlandı.

Seviye: sıfır → ileri · Ekosistem ayrı bölümde

§ 1Bu sayfa nasıl kullanılır

Bu sayfa React'i anlatmaz. React öğrenirken karşına çıkacak terimlerin listesidir. Her satırdaki terimi kendin araştıracak, resmî dokümandan okuyacak ve kod yazacaksın. "Kısaca" sütunu sadece terimi tanıman içindir, öğretmek için değildir.

React, tarayıcı tarafı iş ilanlarında en sık istenen kütüphanedir. Rozetler gerçek öğrenme sırasına göre dağıtıldı. MÜLAKATTA SIK rozeti, iş ilanlarında ve mülakatlarda sık geçen çekirdek konuları işaretler (en az bir çalışan örnek yaz): bunlar "React biliyorum" diyen birinin cevaplayamaması affedilmeyen sorulardır.

Sıra önemli

React'e JavaScript bilmeden başlamak en yaygın hatadır. Önce 01 — JavaScript sayfasındaki closure, `this`, destructuring, spread, array metotları (map/filter/reduce), Promise ve async/await maddelerini bitir. React'in yarısı aslında JavaScript'tir. Tip güvenliği için de 02 — TypeScript sayfasına bak; bugün React projelerinin çoğu TypeScript ile yazılıyor.

State'in davranışı
Anahtar kelimeKısacaNotDoküman

state as a snapshot Her render kendi state değerini "dondurulmuş" görür MÜLAKATTA SIK `setCount(count+1)` üç kez üst üste yazınca neden 1 artar sorusunun cevabı burada react.dev

hook çağrı sırası React hook'ları isimle değil, çağrılma sırasıyla eşler TEMEL Yukarıdaki kuralın nedeni budur; mülakatta "neden koşul içinde olmaz" diye sorulur react.dev

useImperativeHandle Bileşenin ref üzerinden dışarıya açtığı metotları belirler İLERİ Nadiren doğru cevaptır; genelde props ile çözülür. Kütüphane yazarken işe yarar react.dev

useMemo Pahalı bir hesabın sonucunu render'lar arası önbelleğe alır TEMEL Ölçmeden ekleme; çoğu yerde faydadan çok gürültü olur react.dev
useCallback Bir fonksiyonun kimliğini render'lar arası sabit tutar TEMEL useMemo'nun fonksiyona özel hali. Sadece `React.memo`lu çocuğa veya bağımlılık dizisine giden fonksiyonlarda anlamlı react.dev
useId Erişilebilirlik için benzersiz, sunucu-istemci uyumlu id üretir ORTA Liste `key`'i için KULLANILMAZ; label/input eşleştirmesi içindir react.dev
useDebugValue Custom hook'a DevTools'ta etiket yazdırır İLERİ Sadece kütüphane yazarken react.dev
useTransition Bir state güncellemesini "acil değil" işaretler; arayüz kilitlenmez İLERİ React 18 concurrent özelliği. `isPending` ile yükleniyor göstergesi verirsin react.dev
useDeferredValue Bir değerin "gecikmeli" sürümünü verir; ağır liste filtrelemede kullanılır İLERİ Debounce'a benzer ama zamanlayıcı değil, React önceliklendirmesidir react.dev
useSyncExternalStore React dışı bir store'a (Redux, tarayıcı API'si) güvenli abonelik İLERİ Genelde kütüphaneler kullanır; `window.matchMedia`, `navigator.onLine` gibi şeylerde işine yarar react.dev
useOptimistic Sunucu cevabı gelmeden arayüzü "başarılı olmuş gibi" gösterir İLERİ React 19. Optimistic UI kalıbının resmî hali react.dev
useActionState Form action'ının sonucunu, bekleme durumunu ve hatasını state olarak verir İLERİ React 19. Kısa süre `useFormState` adıyla anıldı, ismi değişti react.dev
useFormStatus İçinde bulunduğu formun gönderim durumunu okur (react-dom'dan gelir) İLERİ React 19. `react` değil `react-dom` paketinden import edilir react.dev
use() Promise veya context'i render sırasında okuyan yeni API İLERİ React 19. Hook değildir: koşul içinde çağrılabilir. Arama: "React use API" react.dev
useEffectEvent Effect içinde kullanılan ama bağımlılık olmayan "olay" fonksiyonu İLERİ Uzun süre deneyseldi; kullanmadan önce mevcut React sürümünde stabil mi kontrol et react.dev

§ 6Performans

Backend'de performans optimizasyonu yaptıysan (ör. .NET, Java) ölçme alışkanlığı tanıdık gelecek; ama React'te performans sezgisi sunucu tarafından farklıdır. Hiç performans çalışması yapmadıysan tek kural yeter: ölçüm aracı Profiler'dır, tahmin değil.

§ 8Veri çekme (data fetching)

API'yi sunucu tarafında yazmak bir iş, tarayıcıda tüketmek başka bir iş; bu bölüm ikincisini anlatır. Basit bir Web API'yi React'ten çağıran küçük bir uygulama yazmak, bu bölümün tamamını tek seferde öğretir. API'yi nereden bulacağın durumuna bağlı:

  • Bir backend biliyorsan → kendi yığınında basit bir REST API yaz: ASP.NET Core, Spring Boot, Django/FastAPI, Express/NestJS veya Go.
  • Backend bilmiyorsan veya yalnızca frontend hedefliyorsan → herkese açık ücretsiz bir deneme API'si (ör. JSONPlaceholder), yerelde json-server veya MSW ile sahte (mock) API yeterli.

§ 14Yaygın hatalar

Aşağıdakiler mülakatta "React'te en sık yapılan hata nedir" sorusunun cevap havuzudur. Her birini kendin bilerek yapıp sonucunu gör; ezberden daha kalıcı olur.

sonsuz useEffect döngüsü Effect state'i güncelliyor, güncelleme effect'i tekrar tetikliyor MÜLAKATTA SIK Sebep genelde bağımlılık dizisindeki nesne/dizi/fonksiyondur (her render'da yeni referans) react.dev

state'i doğrudan mutasyon `user.name = "x"` veya `arr.push(y)` yazmak MÜLAKATTA SIK React değişimi fark etmez, ekran güncellenmez react.dev
türetilebilir state'i saklamak Hesaplanabilecek değeri ayrı state'te tutmak TEMEL İki kaynak birbirinden kopar (senkronizasyon hatası). Render'da hesapla react.dev

§ 15Özet — bu sayfadaki öncelik sırası

Yukarıdaki listeyi baştan sona sırayla çalışma. Aşağıdaki sıra, "React biliyorum" cümlesini savunulabilir hale getirmenin en kısa yoludur.

  1. Önce React değil, JavaScript

    Closure, `this`, destructuring, spread, map/filter/reduce, Promise, async/await, ES modülleri. Bunlar olmadan React'te yazdığın her satır ezber olur. 01 — JavaScript sayfasındaki ilgili maddeleri bitir.

    Sıra: 1 · Varsayılan: bunlar olmadan devam etme. İstisna: işte mevcut bir React projesine katkı veriyorsan JS ve React'ı paralel yürüt, eksik JS konusunu karşına çıktıkça kapat (genel bakış § 1); JS'i zaten iyi biliyorsan doğrudan 2. adıma geç.
  2. Kurulum ve temel kavramlar (§ 1 – § 2)

    Vite ile proje aç. Bileşen, JSX, props, children, koşullu render, liste + key, Fragment, StrictMode. CRA ile başlayan eğitimlere takılma.

    Sıra: 2 · Rozet: MÜLAKATTA SIK + TEMEL
  3. State ve render mantığı (§ 3)

    useState, state'in snapshot doğası, functional update, immutability, lifting state up, controlled vs uncontrolled. Buradaki "state as a snapshot" konusunu anlamadan hook'lara geçme.

    Sıra: 3 · En sık sorulan mülakat alanı
  4. Hook'lar: useState, useEffect, useRef, useContext, useReducer (§ 4)

    Bu beşi günlük işin %90'ıdır. "You Might Not Need an Effect" sayfasını baştan sona oku; React'te yazacağın kötü kodun çoğunu bu tek sayfa engeller.

    Sıra: 4 · Hook kurallarını ve nedenini ezberle
  5. Context (§ 5) ve bileşen kalıpları (§ 10)

    Prop drilling → lifting state → context sırasını kur. Custom hook yazmayı öğren; Tek sorumluluk ve kompozisyon fikri burada karşılığını bulur; SOLID bilmiyorsan § 10'daki tanımla başla.

    Sıra: 5 · SOLID/kompozisyon bilgisi varsa işe yarar
  6. Veri çekme (§ 8) — basit bir Web API ile

    Önce fetch + useEffect ile elle yaz, race condition'ı bizzat gör. Sonra TanStack Query'ye geç ve neyi çözdüğünü anla. Kendi backend'in varsa CORS'u o tarafta çözmeyi de dene (ör. .NET, Express, Spring, Django/FastAPI; satırlar § 8'de); yoksa JSONPlaceholder veya MSW ile çalış ve Vite proxy'sini dene.

    Sıra: 6 · Backend bilgisi varsa burada avantaj
  7. Yönlendirme (§ 9) ve formlar (§ 7)

    React Router ile 4-5 sayfalık bir uygulama; React Hook Form + Zod ile bir kayıt formu. İkisi birlikte "gerçek uygulama" hissi verir.

    Sıra: 7
  8. Yaygın hatalar (§ 14)

    Bu tabloyu mülakattan önce tek başına tekrar oku. Buradaki 16 maddeyi bilen aday, "React'e yeni başladım" izlenimi vermez.

    Sıra: 8 · En yüksek getirili tek tablo
  9. Performans (§ 6) ve test (§ 13)

    React.memo/useMemo/useCallback üçlüsünü ölçerek öğren. RTL + Vitest + MSW ile birkaç test yaz; bu aynı zamanda "TDD" ve "mock" pratiğini somut örneklerle kazandırır. Backend'de test yazdıysan kavramlar tanıdık gelir; hiç test yazmadıysan önce tek bir bileşen için "render et → kullanıcı gibi etkileş → sonucu doğrula" döngüsünü kur, mock'a sonra geç.

    Sıra: 9 · Backend test kavramlarına yakın (test geçmişi yoksa orta zorluk)
  10. State yönetimi (§ 11) ve React 18/19 (§ 12)

    Redux Toolkit'in `createSlice`'ını ve Zustand'ı tanımak yeter. Server Components ve Actions'ın yeri hedefine bağlı:

    • Backend ağırlıklı rol veya Vite SPA hedefi → en sona bırak; mülakatta "duydum, henüz kullanmadım" demek doğru cevaptır.
    • Next.js (App Router) veya React Router framework modu kullanan pozisyon/proje → Server Components, Server Actions, Suspense ve streaming çekirdek konudur; 4–5. sıraya al, "kullanmadım" yeterli bir cevap değildir.
    • Frontend uzmanlığı hedefi → React 19 özellikleri (use, useActionState, useOptimistic, form actions) orta öncelik.
    Sıra: 10 · Hedefe göre öne alınabilir

Mülakatta dürüst ol

React'i derinlemesine kullanmadıysan "Küçük projelerde kullandım, derinleşmedim" demek, bilmediğin bir konuda yanlış cevap vermekten her zaman iyidir. Bu sayfadaki § 2, § 3 ve § 14 tablolarını bilirsen o cümleyi rahatlıkla kurabilirsin.
